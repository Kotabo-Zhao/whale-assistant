结论与审计范围

本应用已经具备个人 AI 助手的主要零件：Android 系统入口、常驻桌宠、Harness 工具运行时、资料导入、长期记忆、后台理解和事项提醒。下一阶段最值得投入的方向是把这些零件组织成一条可信、可解释、不中断的用户流程，而非继续堆叠入口。

审计基线：2026-10-31，主仓库 HEAD 87475ea1，包含当前未提交的界面与通知气泡修改。此次为源码与文档审阅，没有重新进行性能压测、耗电测试、真实通知采集或大规模数据迁移实验。下文“已确认”指代码事实，“风险”指待测推断，“方案”指尚未实施的设计。之前单元测试与真机预览结果不替代本次全面验收。

历史《鲸鱼娘助手开发状态》仍描述 100 条记忆和直接调用模型的旧桌宠，已落后于当前代码。不能据此判断现有版本能力；应建立按构建版本维护的能力矩阵。

一、底层架构与模块边界

当前系统有三套表现层：React + TypeScript + Vite 的 Capacitor 主界面；Android 原生桌宠、气泡与系统分享入口；运行在本地 Harness WebView 中的对话界面。React 通过 Capacitor 插件调用 Kotlin；Kotlin 管理权限、存储、后台作业、悬浮窗和运行时生命周期。

运行时层由 Android 内的 PRoot/Ubuntu 环境、Node/dsh、工具与插件组成。Harness 监听 127.0.0.1，经鉴权 HTTP/WebSocket 提供会话服务；桌宠客户端也接入这个 Harness。它不是一套完全脱离运行时的轻量聊天客户端：运行时未启动时桌宠聊天会报不可用。

模块地图：RuntimeStore/RuntimeSupervisor/RuntimeLaunchResolver 负责环境与启动；MobileRuntimePlugin 是桥接边界；OverlayBallService 负责桌宠浮窗；CompanionBubbleChat/History/Window 负责对话；WhaleMemoryShareActivity 与图片/文档导入负责采集；CompanionKnowledgeStore 保存资料；CompanionMemoryStore/MemoryMigrationDatabase/MemorySearchIndex 负责记忆；UnifiedUnderstandingStore/UnderstandingQueue/BackgroundUnderstanding 负责通知等后台理解；SharedMemoryJobs 负责资料回填；提醒、日历、事项模块负责后续行动。

优点：资料与记忆位于应用私有目录，不直接绑在可替换 rootfs 上；运行时有完整性、鉴权和生命周期护栏；工具能力可复用；系统入口不必依赖主界面常驻。

代价：三套 UI 容易产生布局与行为差异；资料、记忆、任务状态分散在 JSON、SQLite 与偏好设置中；主会话与桌宠虽然复用引擎，也不意味着默认就是同一个会话。维护成本集中在跨边界一致性。

建议维持现有技术栈，先抽出 ConversationRepository、KnowledgeRepository、MemoryRepository、JobCoordinator、ModelGateway 五个稳定接口，不进行一次性大重写。UI 不直接拼接存储语义或决定模型策略。

二、记忆系统实际如何工作

典型链路：分享文字/图片/文件 → 获取读取权限并复制或解析 → 本地资料 → 持久任务 → 模型提取 claims → 长期记忆 → 对话时通过工具检索 → 回答。通知则经过来源授权、采集、后台队列、模型理解和候选/事项处理。保存、理解、检索、引用是四个不同阶段，不能用一个“成功”统称。

长期记忆：CompanionMemoryStore 同时保留旧 JSON 与数据库模式；数据库搜索走 MemorySearchIndex。管理页已有 50 条分页接口，搜索空查询使用每页 10 条。索引是自建词项表、规范化子串与相关词匹配，不应称作向量语义检索。相关候选路径存在 200 条截断；这与总记忆容量不是同一个限制。

资料库：CompanionKnowledgeStore 仍整库加载 JSON，MAX_ITEMS=100、MAX_TEXT=8000、MAX_BYTES=512000。因此“长期记忆解除条数限制”不等于“全部资料不限量”。它也是新资料问答不可靠的一个可能来源，不能仅凭代码断言用户某次失败由它导致。

回填：SharedMemoryJobs 使用独立 shared-memory-jobs-v1.db、来源 ID/文本哈希/事件 ID 去重、attempts/next_at 与 JobScheduler 持久调度。模型完成后检查资料未变化，再写记忆，最后删除任务。记忆写入与队列删除不在同一数据库事务，进程在两者之间死亡存在重复请求/重复处理窗口，应以稳定事件 ID 和幂等提交收口。

模型策略：桌宠复用 Harness 当前模型与工具；资料理解代码却直接读取 deepseek 凭据并使用 deepseek-flash。更换主对话供应商不保证后台随之工作。需要统一模型能力与凭据解析，而不是再次要求用户配置一遍。

状态语义：分享模型结果 source=shared_understanding，写入 status=confirmed，但主动对话策略又用 confirmedAt 判断是否由用户确认。这不一定造成运行错误，却让“模型提取”和“用户确认”混用同一状态，容易误导 UI 和后续逻辑。

删除机制已有内容哈希、来源事件、近似签名抑制；它能降低自动重建，不能证明任意语义改写都不会重建。建议保存明确的来源删除墓碑、衍生记录关系和删除代次；用户主动重新导入时提供恢复选择。不要把相似度阈值当作删除的唯一保证。

三、资料解析与问答闭环

已确认的边界：文档输入上限 64 MiB；文本提取上限约 8000 字；PDF 文本路径最多 50 页；扫描 PDF 图像路径最多前 3 页。代码有 DOCX/PPTX/ODT/XLSX 和 PDF 分支，但这不代表所有版式、嵌入图片、公式、加密或损坏文件都可正确理解。格式支持应区分“接收”“提取文字”“识别图片”“保留结构”。

优化方案：原始文件、解析文本、文档分块、模型摘要、长期事实分开保存。先可靠接收，再异步分块；每个分块记录页码/段落/工作表与内容摘要。长文不要把前 8000 字作为全文替代品，改为分块检索、按需读取和带引用回答。

统一状态：已保存 → 等待处理 → 正在解析 → 已解析/部分解析 → 正在整理记忆 → 可用于问答。失败区分权限过期、格式不支持、凭据缺失、网络失败、预算耗尽；保留可重试任务，不反复消耗模型费用。

“鲸鱼娘不知道新资料”的排查应按顺序展示：文件是否落盘、提取是否覆盖目标位置、任务是否完成、事实是否写入、工具是否调用、工具结果是否引用。给用户一个“用这份资料提问”入口，把 sourceId 明确带入当前会话；普通问答仍由模型自主选择检索工具，不用关键词规则替用户分解意图。

图片需保留原图对象与视觉描述的关联，问答可重新读取图片；视觉模型是否可用应通过供应商能力检测确认，不能仅凭模型名称认定支持。分享入口只能接收来源应用实际授予的数据；微信/小红书是否暴露图片 URI 必须逐版本实测。不能承诺读取其他应用私有内容。

四、UI 与易用性重构方案

建议一级导航：对话、记忆、事项、我的。资料作为记忆页内的独立分区；工作台、插件、运行环境、设备自动化收进“我的 → 高级工具”。首页优先显示继续对话与最近待办，不同时铺开运行时诊断、权限说明和所有管理列表。

记忆页：顶部搜索，分类筛选，最近/来源/类型排序；默认卡片仅显示标题、两行摘要、来源图标、处理状态与时间。点击展开详情、证据与关联资料；左滑显示删除按钮，点删除后短暂可撤销。批量管理单独进入选择模式，避免卡片堆满按钮。当前代码已经有折叠、摘要和分页相关实现，重点是统一体验，不是从零再做一套。

资料页：图片缩略图、文档类型图标、文件名、解析覆盖范围；明确显示“仅解析前 3 页”等部分成功信息。详情采用全高页面，顶部预览，下方摘要、问答、关联记忆，避免嵌套小滚动框。保留失败原因与一键重试入口。

会话页：置顶、今天、最近七天、更早分组；分组折叠、搜索、重命名、归档、批量删除。当前列表已支持默认显示五条与展开；后续应解决展开后长列表的加载与导航，而不是只增加折叠按钮。

桌宠：角色周围仅保留轻量通知；聊天展开后使用可调整高度的消息区域、独立左右气泡、底部固定输入栏。键盘出现时输入栏位于键盘上方，历史区收缩并保持滚动锚点；正在阅读旧消息时不要强制滚到底部。图片先显示缩略图，点开预览，加载失败保留重试。

动画：待机用呼吸、眨眼、轻摆；思考用视线移动与手臂动作；回复完成用短动作后自然回待机。优先状态过渡与动作打断规则，避免每次消息都重启整个循环；后台不可见时停止绘制，尊重减少动态效果。此次未重新逐帧检查当前独立部件动画质量。

统一设计规范：正文建议 15–16sp 等效字号，说明 12–14，触控区域至少 48dp，间距采用 4/8/12/16/24；手机页面留出 16dp 主边距。浅色与深色分别定义文字/边框/背景语义色，原生与网页共用设计令牌的生成源。实际字号需结合系统字体放大验收。

可访问性：TalkBack 标签、焦点顺序、非颜色状态标识、200% 字号与横屏布局；错误信息用可执行动作替代纯错误码。高级诊断仍可展开查看。

五、性能与可靠性风险

P0 数据体验：资料容量硬限、解析截断、后台模型配置分叉，会直接影响“保存后能回答”。先完善状态与证据，再扩容。

P1 大数据：资料整库 JSON 加载/重写，长期记忆若干修改和备份路径也调用 load() 取得全量数组。搜索已有索引并不代表写入、导出与管理都能大规模运行。建议行级数据库操作、游标分页、流式备份；用 1千/1万/10万条合成数据测量，而不是直接删掉所有边界限制。

P1 调度：多套单线程 executor 与两条持久队列各自管理重试，错误状态和预算难以统一。保留 JobScheduler 也可以，不必为了框架名称改为 WorkManager；关键是任务领取租约、幂等结果、可取消、断点和失败分类。

P1 桌宠资源：聊天链路创建 WebSocket 与 OkHttpClient，长超时等待可能增加连接和生命周期管理负担；需检查关闭/取消路径并测量，不在没有数据时认定泄漏。动画、透明窗口、图片解码与 WebView 同时存在时需观察主线程和 GPU 帧耗时。

P1 运行环境：PRoot/Node/WebView 与原生常驻叠加，冷启动和常驻内存存在结构性成本。保留已验证启动缓存，不重新加入每次 dsh --version 探测。测量后再决定空闲降载或预热；用户手动停止后不可自动重启。

P2 UI：三套界面重复样式、持续增长的服务类及重复状态提示提高回归风险。优先拆职责、复用设计令牌和状态组件，避免仅用更多 CSS 覆盖修复布局。

性能验收建议（目标，不是当前测量结果）：可见交互 P95 <100ms；1万条记忆检索本地 P95 <300ms；解析在后台，不阻塞输入；60Hz 屏幕主要动画帧预算约16.7ms；重复打开关闭聊天后无持续增长的进程内存趋势。网络模型首字延迟单独统计，不混入本地 UI 耗时。

六、隐私、备份与系统边界

保留现有来源授权、撤权代次、锁屏/静默时段、回环鉴权与插件信任边界。文档和通知是外部输入，模型阅读它们时不能把其中的指令自动提升成用户命令；工具执行权限应依操作风险控制，同时满足用户让鲸鱼娘使用完整工具能力的需求。

统一备份应包含资料元数据、原始对象清单、记忆、删除墓碑、任务状态、会话映射与 schema 版本。凭据不进入明文备份；恢复先预检校验、显示覆盖范围，再事务切换。提醒恢复后重新核对，防止批量误触发。当前存在不同备份编码和大小边界，不应把某条旧格式备份接口等同于全量灾备。

迁移方案：旧库快照 → 分批复制 → 数量/摘要/关联校验 → 原子切换活动版本 → 保留可验证回退点。迁移失败不得清空旧数据。回退要说明新版本新增数据如何保留，不能只证明旧 APK 能安装。

Android 对后台作业和跨应用读取有系统边界。静默保存可不跳主界面，但来源 URI 授权不足时仍需解释失败；后台任务可恢复，不等于系统保证立即运行。

七、功能拓展与优先级

优先做：回答附来源卡片；资料处理进度与重试中心；从资料直接提问；跨桌宠/主界面的会话续接与当前会话提示；删除可撤销；记忆修正和来源追踪。这些功能直接修复用户已有痛点。

第二阶段：词法检索结合语义向量与重排；按需读取原文件；记忆冲突、过期和有效时间管理；事项关联资料、明确改期与提醒联动；每日简报由用户选择时间和范围。向量索引只在离线评测显示召回不足时引入，不把它当成万能修复。

第三阶段：语音输入/朗读、跨设备加密同步、可导出的个人知识包、主动对话的主题与频率偏好。跨设备同步要先解决对象身份、删除墓碑和冲突策略；不要直接同步整个 SQLite 文件。

暂缓：无边界后台持续推理、全应用自动监听、一次性重写所有 UI、无评测地加入复杂知识图谱。这些投入大且容易放大耗电、隐私和一致性问题。

八、实施路线与验收

阶段 A：可信闭环。统一状态与错误码；修正模型配置分叉；补充 sourceId 问答与来源引用；区分用户确认和模型推断。验收：分享后不跳主界面，处理状态可见；成功/部分成功/失败均准确；问资料时可定位原文。

阶段 B：存储和恢复。资料迁移到数据库，文件对象化与分块；记忆写入改行级事务；统一任务幂等与删除代次；补全备份与回退。验收：在复制中、模型返回后、结果提交前后杀进程，重启无丢失/错误重建；删除后重试旧任务不能复活内容；备份恢复前后数量与摘要一致。

阶段 C：界面收敛。统一四个一级入口、卡片详情、会话归档、桌宠键盘适配与图片预览。验收：小屏/大字/横屏无关键按钮遮挡；长列表不把操作入口挤出屏幕；输入、滚动、图片展开不相互抢焦点。

阶段 D：性能与主动能力。建立冷启动、检索、解析、内存、耗电基线；优化确认的热点，再增加语义检索和主动简报。验收：对同一设备、数据集、亮度与网络条件做前后对比，记录分位数和失败率。

估算仅作规划：A 约3–5个开发日，B 约7–12日，C 约5–8日，D 的基线和热点修复约4–7日；不含长周期后台观察、外部模型问题及新功能完整上线。以阶段验收而非日期承诺为准。

荣耀真机矩阵：图片、短文、长PDF、扫描PDF、DOCX、PPTX、XLSX、损坏/加密/超限文件；微信/小红书/文件管理器来源；在线/离线/代理/撤销权限/锁屏/重启/服务重启；默认与大字号；1千至10万条合成数据。每次记录构建号、输入摘要、步骤、预期、结果和日志，不采集真实隐私内容作为性能数据。

九、源码证据索引与审计局限

主要依据：AGENTS.md（启动、桥接、打包边界）；docs/ARCHITECTURE.md（架构与信任边界）；package.json（前端技术栈）；CompanionMemoryStore.kt（数据库/旧格式、分页、备份）；MemorySearchIndex.kt（词项索引与候选限制）；CompanionKnowledgeStore.kt（资料硬限与整库读取）；SharedMemoryJobs.kt（持久队列与后台模型）；CompanionSharedMemory.kt（来源和确认语义）；BackgroundUnderstanding.kt（后台预算与重试）；WhaleDocumentImport.kt（格式、页数与截取）；CompanionBubbleChat.kt（Harness 会话复用及图片协议）；CompanionWorkspace.css、SessionManager.tsx/css（当前折叠与摘要）。Android 文件位于 android/app/src/main/java/io/deepseekharness/mobile/companion/。

本报告没有逐行审计全仓库、外部 Harness 依赖与所有插件，没有新测 CPU/耗电/帧率，也没有验证全部文件格式和来源应用。性能项和复杂恢复项是明确的验证计划，不是已复现缺陷清单。现有 UI 未提交修改保留；本次只新增报告，不改变应用行为。

十、Agent 与记忆的交互设计：让模型理解，让系统保证一致性

设计原则：用户原话直接进入 Agent，由模型理解目标、决定是否检索和选择工具；不通过关键词规则把问题机械拆成固定任务。系统负责提供可发现的工具、授权边界、可靠状态和资源预算，不能代替模型猜测用户意图。也不能只给一句“需要时查询记忆”就认为交互闭环完成。

会话历史解决“刚刚说到哪里”；长期记忆解决稳定偏好、事实与约定；资料库保存可回看的原始证据；事项库维护行动与时间；工作记忆只保存当前任务的临时证据。它们可以统一检索，但不能互相冒充：模型摘要不是原件，对话日志不是全部都应保存的长期事实。

10.1 本次新增的代码证据

CompanionBubbleChat.kt 的提示允许“未知关键词时查询最近资料”，但插件 mobile_knowledge_search 和 CompanionKnowledgeModel.kt 都拒绝空 query。这是已确认的契约不一致，可能使“刚保存的那张图”无法正常定位，尚未证明是用户之前每次失败的唯一原因。

资料工具最多返回 3 条、每条约 1000 字摘录，输出包含 source、createdAtMs、excerpt、excerptTruncated，却没有稳定 recordId、分页游标或按 ID 读取正文的能力。模型即使看到截断，也没有完整的下一步读取协议。

长期记忆工具已有搜索、保存、删除，使用 nextOffset 翻页；插件对 offset 的说明仍写 0–100，与原生数据库路径支持的更大范围不一致。应统一说明、校验和测试，不能仅修改提示词。

这些证据来自当前源码；手机内置 rootfs 是否已经携带完全相同的插件版本，需通过构建清单与设备文件核对。本次没有更换手机插件。

10.2 对话前提供什么上下文

每轮只提供简短能力清单：可用的记忆/资料/事项工具、实际授权状态、当前会话 ID、用户明确选中的资料 ID，以及相对上轮发生变化的内容版本。不要把全部资料和记忆自动塞入提示词。

对于“刚才保存的图片”，以分享事件和稳定 sourceId 建立引用；会话没有确定引用时，模型调用最近资料列表。存在多个候选时展示缩略图或标题供用户选择，不凭时间猜成确定事实。

新资料完成理解后发布带 sourceId/revision 的状态事件，使下一轮刷新能力上下文并使旧检索缓存失效；不强行插入用户正在进行的回答，也不为了更新记忆另开会话。来源名称等可由外部控制的文本仍按不可信数据处理。

10.3 建议的工具协议

memory_search：统一搜索入口，可筛选 memories/documents/tasks，支持关键词、时间、来源和游标。返回稳定 ID、摘要、来源、更新时间、确认状态、匹配类型及是否还有结果。若保留原有工具名，可在其后接同一个 Repository，兼容现有插件。

knowledge_recent：列出最近保存或理解完成的资料，支持类型和状态筛选。空关键词的含义明确，不依赖模型猜约定。

knowledge_read：按 ID 和版本读取指定分块、页码或范围；返回 nextCursor、覆盖范围和原文定位。对图片提供受授权控制的原图/缩略图读取路径，并检查当前模型视觉能力。

memory_upsert：新建、修正或替代记忆，包含 expectedRevision、来源证据和 operationId；返回 saved/pending/conflict，不能只返回笼统成功。用户说“我现在住上海”时保留旧事实的历史与失效时间，而不是无声增加互相矛盾的两条现行事实。

memory_forget：按 ID 或已核对的范围删除，返回删除数量、衍生资料处理范围、墓碑版本与可撤销期限。语义检索仅用于找到候选，删除执行由确定的 ID 集合完成。

job_status：查询处理状态、失败原因和可重试性；告诉 Agent 资料仍在处理中，避免把“还没有结果”说成“用户没保存”。

所有工具统一返回 errorCode、retryable、revision、coverage 等结构字段。空结果、未授权、未处理、解析不完整、工具不可用是不同状态；不让模型把它们一概解释为“不知道”。上述为拟议协议，尚未实现。

10.4 读取与回答流程

用户发问 → 模型判断需要个人事实或原始资料 → 调用搜索/最近列表 → 根据结果决定改写查询、翻页、读取原文或图片 → 核对时间和冲突 → 回答并附可点击来源。模型可以自主多步检索，系统只对时间、费用和单次返回大小设可观察预算。

优先精确定位 sourceId，其次关键词与元数据，再按评测需求增加语义召回和重排。检索失败时可换词和扩大范围，但不能无限循环；达到预算后明确说查到了什么、缺少什么，不编造资料内容。

普通闲聊不必每次查询数据库。涉及个人约定、过去资料、时间变化的回答，应在工具说明和 Agent 指导中强调核验；这是模型行为指导，不是硬编码关键词路由。

回复卡片区分“你确认过的事实”“资料中的描述”“我的推断”，必要时显示原文页码。不要向用户展示内部思维链，只展示执行状态和证据。

例如：问“刚保存的合同什么时候到期？”→ recent 定位合同 → read 检索到期条款和页码 → 回答日期并附来源。若仅解析到前三页而期限在后文，继续处理相关页或明确覆盖不足，不能根据摘要猜。

10.5 写入、纠正、遗忘和主动对话

明确说“记住我不吃香菜”：模型调用保存，按用户已有自动保存偏好返回已保存或待确认；不重复要求全局授权。对话中的临时假设、引用他人观点和模型自行推断，不能直接变成用户事实。

背景理解输出事实候选与证据；用户确认状态独立于可检索状态。模型可以读取未核实资料，但需知道它不是用户确认过的事实。

“我改主意了”应更新对应事实并维护有效时间；关联事项的改期需更新提醒版本，旧提醒触发时核对版本。模糊指代先读取当前关联记录，仅在确有歧义时询问。

“忘掉这份资料”：明确区分删除原文件、长期事实、历史会话引用和后台任务。默认作用范围应在产品中事先定义；结果回执说明实际范围。删除代次使在途任务不能把旧内容写回来；已发送到外部模型的数据无法通过本地删除撤回，不能承诺彻底远端遗忘。

主动对话应由待办临近、资料理解完成、用户选择的简报时间等事件触发候选，再由模型判断是否有帮助并组织语言。系统负责安静时段、频率上限、去重和锁屏内容控制。不要定时把全部记忆发给模型，也不要反复用同一条偏好搭话。通知卡片允许稍后、不再提醒、进入原会话。

10.6 连续性、权限与成本

桌宠与主界面共享 ConversationRepository；“继续当前对话”和“新话题”有明确行为，重启恢复 sessionId、作用域与消息锚点。必要时提供显式切换会话，而非静默把所有桌宠消息灌进用户正在做的另一项工作。

会话上下文压缩保留任务目标、未完成事项和证据 ID；长期记忆仅保存可跨会话复用的内容。不能把保留20条显示消息等同于模型只记得20条，也不能把持久 sessionId 等同于无限上下文。

工具开放与授权约束兼容：不人为剥夺鲸鱼娘的正常工具；存储层仍执行用户开关和来源授权。提示词中的“不要读取”不能代替后端权限检查；应验证桌宠开关是否在实际调用链执行，而不只存在于提示文本。

缓存以 scope/sourceId/revision/model 为键；资料改变、撤权或删除立即失效。检索工具默认返回小摘要，模型按需展开，降低 token 与隐私暴露。后台和前台共用模型能力解析、预算与错误分类，允许用户分别选择模型，但不出现隐式配置分叉。

10.7 交互验收与实施顺序

第一批：修复最近资料契约；增加稳定 ID、分页与按 ID 读取；统一实际权限检查；将处理状态提供给 Agent；回答附来源。优先于引入向量库。

第二批：记忆更新/纠正/删除版本协议，明确确认状态，联通来源与任务幂等，验证模型不会把旧数据写回来。

第三批：跨入口会话续接、压缩上下文、事件式主动对话，以及经过评测的混合检索。

固定验收集：刚分享一张图后立即提问；长文答案在截取范围之外；多份相似文件指代不清；同义词提问；更新住址；撤销授权；删除期间后台返回；服务重启后追问；主界面切回桌宠；资料里包含诱导调用工具的文本；离线处理失败；切换模型供应商。

除单元测试外，需要在隔离数据集上运行真实 Agent 工具轨迹评测：是否选择正确来源、是否读到充分证据、引用是否支持答案、纠正是否只改目标事实、删除是否复活、无关问题是否多余检索、每轮延迟与 token 成本。仅工具接口测试通过不能证明模型会正确使用。先建立基线，再确定召回率和调用成功率目标。
