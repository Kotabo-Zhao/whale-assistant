# Harness 绑定会话的桌宠并发缺口

## 验收范围与当前结果

基于 0.3.8-preview.35（code 80），在 AYANEO 0031BRHA01029239 运行真实模型测试。此次仅更新验收代码，不发布新的主应用安装包。

`WhaleConversationalTaskTest.independentReportIsAcceptedDuringAnotherReply` 增加 `boundSession=true` 参数：创建专用 Harness 会话，设置 read-only 权限，通过现有 `resumeSession` 持久化桌宠绑定，再运行原有并发断言。测试不读取用户已有会话，使用唯一标记的合成交接资料。

流程为连续发送长童话与另一份独立差异报告需求，保留未发送的第三句草稿。要求报告在首轮仍待回复时接取、显示接取回执，并最终只生成一份完成报告。绑定模式不放宽这些断言。

实机绑定模式在 47.226 秒失败，错误为「首轮回复已结束，独立工单尚未接取」。这是并发验收失败；不能用随后可能串行接取来宣称满足要求。该断言本身不区分首轮成功结束与失败结束，不能据此推断首轮长回复的完整质量。原始测试输出保存在本地 `build/bound-session-overlap-baseline.log`，不提交设备原始日志。

随后同一设备的普通桌宠路径通过，耗时 90.642 秒：首轮尚未结束时已接取独立任务，显示回执、保留第三句草稿，最终唯一报告完成。输出保存在本地 `build/direct-session-overlap-control.log`。这支持两条会话路径存在差异，不代表绑定路径已修复，也不是耗电或长时稳定性结论。

## 已确认的代码原因

- `CompanionBubbleWindow` 发送排队消息时，只有 `chat.handoffSessionId() == null` 才启动旁路分类。分类完成后又重复检查该条件。因此绑定会话不会使用已实现的独立任务及时派发路径。
- `WorkerRuntimeWake.submit` 与 `WorkerDashboardStore.submit` 当前没有保存来源会话的参数。插件 `workers.js` 的 `acceptSubmission` 固定使用 `session-whale-task-desk` 作为父会话。
- Worker 启动时实际读取 `row.owner` 对应父会话的权限预设，再赋给 Worker；custom 预设会受阻。只删除前台两个限制，会改用任务台的父会话与权限，不能当作完整修复。

## 修复必须满足的约束

1. 原生交办队列、待授权暂存、恢复重放和 Worker 台账保留同一来源会话与命令编号；不能在重试时变成任务台任务。
2. 来源会话由原生绑定状态确定，不能由分类模型输出指定。执行端确认来源存在，继承该会话当前权限。未知或无法解析的权限保留受阻工单，不能退回较宽的默认权限。
3. 独立任务只收到新消息原文；补充、更正、指代及取消继续走原会话，不另建工单。原会话回复、第三句草稿和回执顺序必须保留。
4. 主应用与插件协议需同时更新并验证；旧运行环境若不识别来源字段，不得静默派发到默认任务台。
5. 验收覆盖绑定 read-only 会话并发、权限更改、待授权恢复、丢失接取确认后的去重，以及普通直聊路径。创作能力仍须遵守来源会话权限与现有草稿预览约束。

## 复现命令

在已配置模型、安装匹配测试 APK、授权测试浮层的专用设备上执行：

```powershell
adb -s 0031BRHA01029239 shell am instrument -w -e class 'io.deepseekharness.mobile.companion.WhaleConversationalTaskTest#independentReportIsAcceptedDuringAnotherReply' -e boundSession true io.deepseekharness.mobile.test/androidx.test.runner.AndroidJUnitRunner
```

省略 `-e boundSession true` 使用原普通桌宠路径作对照。测试结束恢复原浮层权限。绑定路径当前不通过，仍是活动目标中的待修复项。
