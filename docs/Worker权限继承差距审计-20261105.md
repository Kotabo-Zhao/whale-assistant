# Worker 权限继承差距审计

本轮直接读取 AYANEO 安装运行环境中的 Harness `0.2.1-rc.1` 实现与声明，再对照移动 Worker。以下结论针对设备当前代码，不代表所有上游版本，也不是权限端到端验收。

## 已确认的接口语义

- `dsh-permission-presets` 的 `current(session)` 返回当前匹配的预设名；没有匹配时返回 `custom`。`custom` 仅是派生显示值，不是 `set()` 的有效目标，也不应作为预设选择事件写回。
- 公开的 `resolve(name)` 返回配置的 `sandbox`、`approval` 和展示信息。预设名称可以自定义，不能只按 `workspace-write`、`danger-full-access` 两个名字判断是否允许写入。
- 其 `permissionState()` 在类型声明中是私有方法，插件不应依赖它。生效沙箱应通过公开服务或官方委派接口读取。
- `dsh-subagent` 导出 `captureDelegatedPolicyOverrides(parent)` 与 `appendDelegatedPolicyOverrides(childSession, overrides)`。前者读取父代理的显式沙箱覆盖，只保留 Auto / Full access 的预设身份；审批策略固定为 `never`。后者将沙箱、审批及必要身份记录到子会话日志，沙箱与审批事件带 `source: delegation`。
- 官方注释要求在子代理启动首次异步等待之前捕获权限，并在尚未发布的子会话创建窗口写入。直接把这两个函数放到当前“创建并发布 Worker 后再切预设”的位置，不等价于官方生命周期。
- `never` 在委派语境下不是为被拒绝的操作自动授权。官方子代理提示要求把越界需求交回委派方，不在子会话中扩大权限。

设备证据：`/opt/dsh/node_modules/.pnpm/@deepseek-ai+dsh-base@0.2.1-rc.1_200d115280452f1f78c282eb1a8fc963/node_modules/@deepseek-ai/dsh-permission-presets/lib/index.js` 的 SHA-256 为 `4f23c620145098d611d04d8363bc6716f49b26930c9141a21dc9a8df2b72ba63`。声明已留在本地 `build/installed-permission-presets-audit.d.ts`。委派实现留在 `build/installed-subagent-audit.js`，函数位于约 408–434 行；这些文件仅作本地证据，未把整份上游代码加入仓库。

## 移动 Worker 的实际差距

| 路径 | 当前行为 | 缺口 |
| --- | --- | --- |
| 启动与续接 | `workers.js` 的 pump 解析父会话，重新读取 current，再对 Worker 调用 set | 能刷新已支持的命名预设；还没有官方委派快照与未发布窗口语义 |
| 未匹配的自定义组合 | 普通任务遇到 custom 抛通用错误，落为 failed；创作通常先被写权限判断挡为 blocked | 应继承可证明的沙箱范围与审批边界，无法继承时明确受阻并保留原工单；不能转换为宽松预设 |
| 自定义命名预设 | 创作只认可两个固定名字 | 合法写沙箱的其他预设名也被误判；需要按生效能力判断 |
| Auto | 普通 Worker 可 set(auto)，创作被固定名称列表拒绝 | 缺少委派审批固定、审核身份继承和拒绝后的人工介入验证 |
| 创作中权限变化 | authorDraft 在异步 ack 后重新检查父权限 | 具有撤权复核，但仍只检查两个名字；改用能力判断时必须保留异步后的复核 |
| 一般 read/device 任务 | 绑定的工具守卫检查工单模式及状态；启动后未按每次调用重新读取父权限 | 需要明确任务权限快照与后续收回的规则，不能声称父会话改权会自动即时更新全部运行中 Worker |

## 下一步实现及验收边界

1. 先接通官方委派创建/恢复生命周期或证明等价的会话创建方式，避免在已发布会话中短暂使用默认宽权限。保持现有工单 id、归属、revision 和输入台账。
2. 用公开权限 API 获取沙箱及 Auto 身份，分别处理命名预设、custom 组合、Auto 和不可用服务；禁止以完整权限作为兜底。
3. 创作许可按实际沙箱判断，同时保留工单专属草稿约束与异步后的撤权复核。允许写工作区不等于允许启用插件、读取其他资料或改动原生应用。
4. 验证只读、自定义只读、自定义可写、Auto 审核允许/拒绝、撤回、恢复、权限服务缺失及进程重启。对每项核对子会话日志和真实工具结果，而非只看 current() 或界面标签。
5. 缺权限时保留原工单，用户调整权限并继续后使用新的可验证委派范围；不得创建重复工单或复活已撤销授权。

此轮是实现前的接口与生命周期审计。未修改运行环境或设备权限，未宣称 custom / Auto 缺口已完成。主应用仍为预览四十七，运行环境仍为 `0.3.58-whale-bound-creation`。
