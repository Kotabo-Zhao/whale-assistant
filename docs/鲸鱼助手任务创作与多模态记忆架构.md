# 鲸鱼助手任务、创作与多模态记忆

## 桌宠与后台如何协作

桌宠保留一个有序聊天会话。用户可以随时从“交办”提交另一项任务。主应用的“事项 → 后台任务”使用相同入口；“我的待办”供用户核实资料中提取的行动项，“执行记录”用于查看桌宠对话的工具操作。

1. Android 先把任务、权限和稳定命令 ID 写入本机原子队列，再向前台返回收据。输入阶段不等待模型。没有选择设备操作时使用只读 Worker。
2. Harness 监听唤醒提示；启动与心跳期间也从持久队列检查遗漏。专用父会话承载直接交办，原聊天保留自己的会话、草稿和问答顺序。每项任务有独立的 Trigger、工单及 Worker 会话。
3. Worker 报告完成、追问、阻塞和失败。用户从任务卡回答或继续；来源授权、依赖、撤回和设备操作互斥沿用 SuperAgent。升级、重启和命令重放均使用原有任务 ID。
4. Android 只在收到任务镜像后刷新可见状态。等待接取的命令与已执行结果分别展示；运行环境不能启动时保留命令，提示用户恢复服务。

`mobile_superagent_read` 分页返回工单、触发依据、决策、订阅、输入、执行与投递健康状态。主会话可查看全局资源；调度器按真实会话身份限制 Worker 的访问范围。处于 Android 严重热状态时暂缓新派工，节电、内存告急或中度热状态下只读任务逐个启动。排队期间前台可继续交办。

领域引擎把报告与待投递回执纳入同一个外层事务。执行器完成外部操作后，将领域状态和对应指令确认一起提交。断开执行时按指令 ID 和代次核对已完成的工作，再决定重试。

### 从普通对话接取工作

预览三在直接桌宠聊天的前一轮未结束时，允许单独判断新消息。只有模型给出完整后台计划，并且明确返回布尔值 `independent=true` 才会提前交办。此时只把最后一条用户原文交给 Worker，检查当下资料、记忆和创作授权，接单结果先在桌宠窗口展示，再按顺序记入对话。已有 Harness 会话继续使用其原有权限。网络故障或模糊意图回到常规对话；提交已经开始而回执不确定时会提示核对工单，不重复派发。

桌宠默认接收自然语言。直连 DeepSeek 时，同一次意图判断区分闲聊、即时资料查证、需要原会话处理的动作，以及适合独立执行的只读工作和工具创作。用户可以用陈述表达需求。目的、材料与缺少的交付物足够明确时，模型可安排任务。原话是工作范围，对话里必要的指代作为补充。模型提供简短标题，用于接单回执和工单列表。涉及设备或外部副作用的操作、已有任务的回答和追加继续走原有授权路径。单纯讨论想法或询问事实不要求建立工单。

自动派工先保存包含唯一指令号的对话检查点，再提交原生持久队列。接单成功后才显示带标题的回执。进程在确认前中断时复用同一个指令号，队列重投和领域工单分别去重。恢复时重新检查资料与记忆权限。用户在模型处理本轮时可以编辑下一条草稿，已接任务独立执行。已建立的 Harness 会话保留其身份与工具权限，由该会话模型决定直接回答、续接已有工作或通过 mobile_workers 分派新的工作。

桌宠长按仍有交办入口。聊天中的手动交办放在会话选项里，任务列表和主应用后台任务页也保留手动表单。工具草稿仍由用户预览、启用。

### 一套编排层怎样管理多个 Worker

同一 Harness 插件运行时安装一套共享的 SuperAgent 工单引擎和协调器。桌宠的明确交办先进入 Android 持久队列，再由固定的交办会话接取。主会话也可以根据用户的目标多次调用 mobile_workers.start。两条路径经过 acceptPhone 生成触发事件、接受决定和工单。协调器驱动派工、补充输入投递和停止，执行队列按工单启动或续接独立 Harness 会话。Worker 的报告再更新工单并返回前台。只读任务可并行，占用手机的设备操作受互斥控制。任务分组和先后依赖由主会话派工时给出。

桌宠对话的 PetIntentRouter 只负责聊天、资料与 Agent 意图分类。明确交办按给定操作直接立工单；跨来源待评估事件可交给当前主会话判断。共享协调器、主会话和意图分类器承担不同职责。系统能由主会话把一个目标拆成多个任务，单次点击“交办”默认对应一个工单。Worker 不能递归派生新的 Worker。

### Worker 怎样获得完成工作所需的权限

预览四把直接聊天和并行识别出的待授权请求存入本机原子文件 `worker-dashboard/permission-requests.v1`。它与 guest 可读取的 `commands.json` 分开。任务卡只展示标题、当前缺少的授权和可执行操作。打开权限设置不会派工；用户明确选择继续后，重新检查知识库、桌宠记忆和会话预设。通过后使用原指令号提交，再清理本地请求。若接取确认中断，重复提交沿用原有队列及领域工单的幂等规则。移除只影响本地待授权请求。

Worker 启动时复制派工会话当前的 Harness 权限预设。这里的派工会话可以是已有的主会话，也可以是承接桌宠持久工单的独立会话。运行时遇到不能直接复制的自定义预设会提示先选择明确的预设。

每次工具调用还需通过当前任务模式的检查。只读任务可以检索资料、文件、公开网页和设备状态；点击、输入、截屏和设备侧文件操作由设备模式提供，同一时间只允许一个 Worker 操作手机。创作模式仅允许汇报和操作本工单绑定的工具草稿，并在写入前核对运行状态、有效授权、工单标识与版本。启用草稿仍由用户决定。

Android 系统授权、Shizuku 或无障碍连接、用户授予的资料及长期记忆访问分别检查。桌宠判断一项工作需要受保护资料时先核对授权，恢复未确认派工时再次检查。设备能力查询会返回实机状态、原因和可行的下一步，具体动作仍以当次工具回执为准。缺少前提时 Worker 可以报告等待或受阻，用户可在原工单补充或继续。任意任务所需的全部权限尚无统一的事前预测，后台不会自行提升权限。

## 助手偏好的分组

主应用设置里的“助手偏好”保留常用开关。“全部助手偏好”进入原生目录，首页只显示桌宠与权限、记忆与资料、通知与提醒、日常助手。宽屏使用双列，窄屏使用单列。选中的页面才创建控件和读取状态。长期记忆统计、本地资料整理、权限检测和通知列表分别在进入对应页面时加载。

统一备份和加密知识包集中在“备份与恢复”，单项导入导出和数据库迁移放在其下的“旧格式与数据维护”。通知采集、后台理解、事项提醒和通知历史独立进入。返回键和标题栏返回使用同一层级，Activity 重建后恢复所在页面和返回路径。桌宠的资料授权链接直达“本地资料”，通知记录入口直达“通知记录”。

## 桌宠的常用入口

点鲸鱼直接对话。长按打开一个紧邻角色的快捷菜单，第一层是桌宠对话、交办任务、存资料和后台任务。来源应用继续接收菜单外的触摸。设备控制集中在“设备与显示”。“我的工具”在菜单和聊天中复用同一个已启用目录，只在展开后读取。聊天中的“会话选项”汇集手动交办、资料授权、转到主对话和新话题。快捷菜单交办与查看任务分别打开同一个 Worker 面板的新建表单与工单列表。

从别的应用长按鲸鱼，选择“存资料”，可以明确选择刚复制的内容、当前一屏、本地文件或文字。剪贴板和屏幕收藏复用快捷设置磁贴的本地接收逻辑，前者只在主动选取时读取，后者需要 Android 授权。聊天中的“存资料”支持保留草稿、编辑另存的文字或给文件附说明。

### 桌宠交互的视觉与输入

对话、交办、资料速存和任务收件箱使用同一组原生控件样式。对话卡顶部显示角色和任务入口，正文随消息内容调整高度。输入区固定提供发送和会话选项。聊天、交办和资料草稿仍由各自的原有会话、工单及接收器保存。任务卡首先展示状态、摘要和当前可执行的回复或继续操作，来源、权限和管理动作按需展开。

角色贴纸取自桌宠现有的睁眼和闭眼原画。交办配星形印记，存资料配心形印记。原画在后台按四分之一边长解码，两帧共用一个小缓存。贴纸只有内容就绪时重绘，独立于桌宠关节动画。浅色和深色界面分别提供适合阅读的消息、链接和表格颜色。

## 桌宠怎样表现任务状态

桌宠使用同一张角色原画、补过遮挡区的身体图和闭眼图。加载线程按悬浮窗尺寸解码，预计算每个顶点的关节与权重。胸部带动头和肩，肩带动肘和腕。侧鳍、两侧头发、双脚及尾根、尾梢分别参与变形。后台回执显示可点击的轻提示，用户打开对话时聊天窗会选择与角色错开的位置。可见时只更新顶点，关闭动效、隐藏或锁屏时停止帧回调。

| 用户看见的状态 | 动作与触发条件 |
| --- | --- |
| 待机 | 头部缓慢侧摆，鳍和尾梢错拍，前臂交替舒展 |
| 接任务 | 成功写入队列后点头、抬手、跃起，快速返回的结果会等接单动作演完 |
| 工作中 | 运行中的任务或前台模型思考让角色前倾，一手收起，另一手反复点按 |
| 等待回答 | Worker 发出追问时歪头举手。仍有别的任务运行时，展示追问后回到工作循环 |
| 完成或受阻 | 完成时双手举起、连续两次起跳。受阻或失败时肩头下沉，再回到实际台账决定的状态 |

## 资料怎么进入记忆

| 用户交给助手的内容 | 处理方式 | 可核对的信息 |
| --- | --- | --- |
| 文本、系统分享附言 | 保存原文，超长文本分块；相同资料保留多个分享来源 | 原句、记录 ID、修订摘要和分段编号 |
| 微信、小红书等应用的链接 | 识别分享中的网址和来源线索。用户可以在详情中提取公开正文 | 链接、页面标题、已获取的正文。页面只提供登录界面时保留原分享 |
| 本地文档 | 系统文件选择器或“存入鲸鱼记忆”；按文件格式解析 | 原件 SHA-256、文件名、解析覆盖范围、分段与版本 |
| 图片和截图 | 保存原件，先在设备上识别中文及拉丁文字；没有识别到文字时沿用已配置的图片理解能力 | OCR 文本和模型描述分别标识，可回看原件 |
| 音频 | 系统解码器读取整条音轨，混为单声道并重采样到 16 kHz，中文模型在本机转写 | 语音段保留原始时间戳；长数字静音仍计入时间，跳过冗余识别。达到资料文本上限时标记部分提取 |

资料库负责保存原文和原件，长期记忆沿用已有后台整理服务，保存抽取结果及其来源。混合检索复用 SQLite 和 BGE 索引。资料授权在读取前检查，按 ID 读取时核验修订摘要。长期记忆的单字和双字精确查询在索引中计数分页，长句先求字符对交集，再核对完整子串，匹配不会因记录较旧而被候选数量截断。资料库也会核对完整子串；匹配不到时根据关键词检索相关片段。管理页支持文件名与分享来源检索。

已有资料分批建立索引，尚未建索引和刚修改的数据参与查询。记录的插入、更新与删除在 SQLite 事务里触发索引失效处理。删除原件沿用原资料墓碑和派生记忆清理规则。

可从系统分享、支持 Android 文字选择菜单的应用、资料页的文件选择器或桌宠的“存资料”入口存入。桌宠速存可以编辑聊天草稿的副本，也可给选中的文件附上说明。来源名称是系统或网址提供的线索，不作为身份认证。网页提取仅访问公开 HTTPS 页面，不携带账号登录状态，不执行网页脚本。列表仅为接近视口的图片请求小尺寸缩略图；打开详情后读取大图。语义模型在最后一次推理后保留一分钟，空闲时释放，关闭语义检索时在在途请求结束后释放。

旧版只转写前十分钟且仍保留截断标记的录音，可在原件详情选择“继续转写后续录音”。续转定位原音轨的十分钟处，把新片段追加到同一原件下。已存片段的编号和文本保留，已删除的片段不会自动恢复。后续无语音时可完成续转而不新增空记录；系统停止解析任务时会退出解码循环，原件仍可重试。

## 主应用导航与工作台

嵌入式 Harness 对话与管理界面使用同一组一级目的地。对话保留原受限 WebView。记忆默认打开资料，也可切换长期记忆和提醒。资料搜索与文件投放在首屏，备份、筛选和批量操作归入次级入口。事项集中处理后台工单、待办和执行记录。工具页聚合已启用工具、功能工坊、创作入口与插件管理。“我的”把设置分成助手与外观、运行与存储、设备与诊断。分组入口同时可见，一次只显示一组配置。搜索会直接列出各组的匹配项。助手偏好管理开关，查看资料统一回到记忆页。

在掌机横屏，导航移到左侧，切换记忆或事项时只隐藏对话。窄竖屏使用底部导航。工作台保留启动、更新与故障恢复操作，在下方提供交办、查资料和打开工具的快捷入口。已确认的桌宠动作继续使用原关节与状态片段。

首次进入时，已保存的语言选择优先；没有选择时按系统首选语言匹配简体中文或英语。模型引导可直接进入本地资料，不要求先安装运行环境或输入密钥。对话及联网模型执行仍使用原有凭据守卫。

## 在来源应用直接投放

| 你在来源应用中能做什么 | 操作 | 入库内容 |
| --- | --- | --- |
| 长按后内容能够浮起 | 将内容拖到可见桌宠，出现“松手存入”时释放 | 文字、网址或临时授权的文件。说明与同批原件一起关联 |
| 有系统分享或选词菜单 | 点“存入鲸鱼记忆” | 来源应用实际交给 Android 的文本、链接、图片、音频或文件 |
| 应用只提供复制 | 复制文字或链接，下拉快捷设置点“收藏剪贴板” | 只读取这次点击时的剪贴内容，保存后回到原应用 |
| 想保存眼前的页面 | 下拉快捷设置点“收藏这一屏”，确认 Android 的单次采集授权 | 在应用私有目录保存一帧原图，停止投屏后在本机识别文字。可以按画面上的字检索 |

可在“记忆 → 资料 → 从其他 App 投放”添加两个系统磁贴。Android 13 起会显示系统添加请求，较老的系统可在快捷设置编辑页手动添加。磁贴独立于桌宠开关。源 App 须发出全局拖动才能把内容拖到第三方窗口，文件需要源 App 提供可读 URI。系统可遮蔽受保护窗口。相关平台行为见 [Android 跨应用拖放](https://developer.android.com/develop/ui/views/touch-and-input/drag-drop/multi-window) 和 [Android 单次屏幕采集](https://developer.android.com/media/grow/media-projection)。

说明和同批各个原件通过资料记录 ID 与原件实例 ID 关联。重复导入会合并同一关系，长说明的各段共用随附原件。按说明搜索、打开详情后可选择原件。Harness 的 `mobile_knowledge_read` 在原有资料授权与修订检查内返回引用，并分别分页读取正文与原件列表。删除原件后它立即从随附列表消失；相同字节以后作为一次新导入，也不会让旧关系重新出现。旧记录缺少关联元数据时不推断附件。

## Harness 如何给应用增加功能

用户可以在“工具”页打开功能工坊或进入创作对话，也可以直接在 Harness 中提出需求。模型调用 `mobile_whale_feature` 查询、读取或提交完整交互页面。Android 独立保存源码和版本，在主应用与桌宠的“功能工坊”提供预览与使用入口。

草稿包含功能标识、标题和单文件 HTML/CSS/JS。编辑已有功能须携带基础版本，防止覆盖同时发生的编辑。启用版本和最新草稿分别保存；启用新版本后可切回上一版。工具在独立 WebView 中运行，无设备桥、文件访问或联网能力。当前适合换算、表单、计算和其他本机交互工具。需要新 Android 权限或新增原生 API 的功能仍走源码修改、签名和安装流程。

桌宠“交办”与主应用“事项 → 后台任务”都提供“读取整理”“创作工具”“操作设备”三种选择。创作任务只拥有草稿工具与工单汇报工具。它可以先向用户提问，其他 Worker 继续接取任务。每次明确的创作交办获得一个稳定的功能标识，草稿归该工单所有。追加要求后可用版本校验修改同一份草稿。

原生接取时将用户的持久交办命令绑定到 Worker。每次提交核对任务状态、分派、修订和撤销状态。等待处理的取消命令立即阻止再次写入；已保存的草稿可由用户查看。进程重启后，执行中的创作任务等待用户明确继续。事项和桌宠任务卡均可打开工单草稿的指定版本，用户在独立预览中试用后可点“启用草稿”。新版本到达时，旧预览不能发布覆盖它。

工坊启用一个版本后，应用和桌宠的“我的工具”都使用同一份已启用工具目录。目录只缓存标识、正式标题、版本和启用时间。启用、停用或回滚会通知可见入口更新，不需要定时扫描。新草稿可以有自己的标题，已启用的入口仍显示正式版标题。点击时重新读取当前启用版本，停用的工具不能由旧入口运行。

生成工具若需要保存结果，可以提供一个 `<output data-whale-result>` 元素。已启用的工具提供宿主“收藏结果”入口。宿主在用户点击时读取一个结果文本，用户可编辑、取消或保存，单条上限 8000 字。保存时再次核对已启用的版本并标注工具来源。工具预览没有这项能力，工具页面不能通过 JavaScript 自行写入鲸鱼资料库。

每个功能拥有单独的本地存储来源。预览与启用版使用不同来源，试用草稿不会改写正式版的 localStorage。

## 任务中心与桌宠详情

后续工单的卡片会标明未完成的前置任务和状态，优先显示需要人工处理的一项。可在当前卡片打开前置任务详情，将回答或继续说明送给对应前置工单；取消的任务保留历史。运行环境 `0.3.56-whale-dependencies` 会记录依赖等待原因，只有原因变化时更新镜像。处于依赖等待的工单不会单独维持五秒心跳。即将投递执行输入时再检查一次前置状态，防止启动过程中前置任务重新进入待处理。已安装的旧运行环境需要通过正常更新流程切换。

后台工单变化优先走原生通知。当通知订阅不可用、或需定期刷新渠道诊断、屏幕陪看与执行记录时，仅在对应页面可见期间安排下一次读取。切走页面即停止定时器，返回时立即刷新；前一次读取尚未完成时不并发发起新读取，页面隐藏前的旧响应不会更新渠道或陪看状态。诊断轮询与设置表单首次载入分开，切换事项页签不会反复覆盖正在编辑的内容。

事项页按 20 项分页，可以筛选待处理、执行与排队、已结束及历史工单，目标筛选在展开时才读取。新交办先写入独立的持久队列，历史浏览不占用该队列的锁。桌宠关闭任务面板后只请求状态计数。任务卡保留状态、摘要、追问和草稿入口；在已完成任务上点“追加信息”才会显示补充输入框。

新原生镜像在同一份原子 JSON 文件的首行保存卡片摘要，仍保留全部历史与本地创作授权。旧镜像可直接读取，未改写的旧文件不会因为打开列表而被批量重写。按目标筛选、依赖检查、原件缺失判断与创作授权有独立回归。打开详情时读取所选工单，每页最多向界面返回 12 条输入、进展或回执。待回答的问题和结果优先展示，长内容可展开，任务范围与接取依据另行折叠。

## 投放后返回原应用

系统分享、文件选择器和桌宠拖放共用原件保存入口。一次最多接收 10 个文件，单张图片限 32 MiB，其他单文件限 64 MiB。投放时保留原件、附言及来源，临时读取权限到此即可释放。系统分享支持多段文字、网页 URI 和 HTML 附言，会合并同一次投放里重复提供的文字。结果提示分别统计待解析、资料库已有和保存失败的文件数。

原件行、说明关联和解析工单在同一笔 SQLite 事务内提交。Android 调度器持久保存唤醒请求，后台每次只解码一份本地原件。资料详情区分排队、解析中、成功覆盖范围和提取失败。失败时可点“重新解析原件”。中断后读取本地原件即可继续，多次中断会停止自动尝试。永久删除原件、删除资料行或恢复备份都会使旧工单失效。检索片段、覆盖状态与工单完成一次提交，重复执行不会重复收录。屏幕磁贴继续只在设备内识字。

语义索引和长期记忆整理各自合并同一批写入的系统唤醒请求。新请求可以提前执行时间，任务执行中收到的变更会保留，结束时按最早时间接续。长期记忆整理每批最多处理 8 条，关闭长期记忆时暂停调度；文件解析与长期记忆开关相互独立。

资料备份包含资料记录，不把待处理工单带入恢复后的资料库。恢复时只认可应用内置索引触发器的精确 SQL，从主记录重建全文索引。兼容本次验证的缺少全文索引表的旧结构。

## 最近投放与原件阅读

“记忆 → 资料”在没有搜索词和筛选条件时显示最近投放。默认两项，展开可浏览最近八份资料。每次主动投放文本、链接、图片、录音或文件都记录资料 ID 与创建时间，原件还记录自身实例标识。重复投放同一份资料会回到最前面。分段正文只占一项，多文件分享分别显示各份原件。记录指针与资料保存处于同一 SQLite 事务，列表不复制正文，也不根据旧库的创建日期猜测历史投放顺序。

点卡片可读原文、截图识字、图片描述、文档正文或带时间的录音转写。长文每页最多三段，直接按分段主键读取，删除某一段后其余分段仍可读。旧原件也可从“查看详情 → 阅读提取内容”进入。收藏阅读可再打开原资料详情进行重试、提问或查看原件。资料详情和阅读页使用主应用同一返回栈，实体返回依次回到上一级；历史位置只保存资料引用。资料页仅在可见时按原生保存、解析、编辑与删除事件重新读取，不设空闲轮询。删除或重新导入时检查原件实例，打开旧卡片不能读到被替换的资料。备份与恢复均不携带设备的最近投放顺序。

## 验收口径

任务验收同时检查真实模型回执和前台可操作性。记忆验收使用含已知原文、截图和录音的样本，测命中集合、顺序、延迟、删除与旧库升级。桌宠分别测绘制成本、可见窗口帧时间、熄屏调度与长时热耗。商用成熟度与动效观感需实机使用确认。本轮数据和限制见[持续开发日志](鲸鱼助手持续开发与真机日志-20261104.md)。

### 预览八 · 多 Worker 结果

原生工单目录在选择具体目标后，先按目标统计全部工单，再应用列表状态与分页条件。结果按完成、需处理、执行与排队、取消分组。各组最多携带四条摘要，每条最多 320 个 UTF-16 代码单元；完整结果按工单 ID 读取。普通列表、收起的桌宠徽标不构造目标汇总。桌宠和应用共用此数据源，刷新沿用已有事件通知。

### 重复投放的来源

同一条资料通过不同入口投放时保存最多十二个不同的来源标签与链接组合。重复来源更新到最近位置。详情在有多个来源时显示折叠的「投放来源」，按最近优先展示，无需额外网络请求。链接只表示资料曾从此处投放，其正文是否已经提取由解析记录单独说明。

### 桌宠窗口收起与重新打开

前台发送队列独立显示三种状态：意图判断中、等待按对话顺序处理、已取得接取或待授权回执。每条消息保留原发送顺序。状态栏由队列变化驱动，展开时按需显示最多十二条消息；收起后重开根据当前请求、队列及待答状态重建窗口，原会话继续执行。这个队列位于服务内存，进程退出后的未交办消息恢复仍需单独实现与验收。

### 服务退出后的后续消息恢复

预览十一将用户在等待期间已经按下发送的消息写入与对话历史同目录、单独存放的 AtomicFile。记录最多十二条，随消息接取更新，不轮询，也不进入对话备份。交办前先记录 handoff，并以消息自身的 UUID 作为后台命令或待授权工单的 ID；启动前台回复前标记 reply。对话历史成功落盘后再核销记录。重启时 queued 可以由用户继续，handoff 和 reply 先核对原工单或对话，避免在结果尚不确定时再次执行指令。未按发送的输入草稿和模型流式输出不属于这份记录。

### 第一条直接模型回复

预览十二在清空桌宠输入框之前，以原用户文本、之前已完成的对话和请求 ID 保存 direct 待处理记录。重新打开窗口时显示原文和重新生成入口，等待用户操作。转入 Worker 时保留请求 ID，先持久化 worker 待处理记录再交办。转入 Harness 时以同一 ID 保存主会话、权限范围和实际提示词后提交。回复结果在开放下一轮输入前写入，旧轮次的异步摘要写入不会再覆盖新轮次的待处理记录。

### 桌宠任务导航与主题

「当前任务」保留执行进展，「待我处理」筛出需要回答、授权或恢复的任务，「全部任务」用于查阅历史。未接取的普通提交只在相关列表第一页显示。具体工单可查看同目标下的其他结果。详情和输入窗口共用 PetUi，主题分支只改变共享标题和视觉样式，不复制任务查询与控制逻辑。
