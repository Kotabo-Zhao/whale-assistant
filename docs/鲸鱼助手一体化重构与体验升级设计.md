# 鲸鱼助手一体化重构与体验升级设计

日期：2026-10-30。状态：待实施设计。适用仓库：Kotabo-Zhao/deepseek-phone-agent。

## 1. 目标与范围

把当前 Android 壳、Harness 对话、桌面鲸鱼娘、插件市场及个人数据功能整理成一个助手：同一会话、同一套设置、同一份任务状态。先解决启动可靠性和信息架构，再逐步优化性能、记忆和主动服务。本文是本轮实施依据，描述目标的章节不代表已经实现。

本轮仅交付设计，不改业务代码、不发布 APK。后续按阶段实施，每阶段交付可回退变更、测试证据和设备验证记录；不能以构建成功代替荣耀 Magic6 验收。

## 3. 用户体验与导航

底部固定一行四项：**助手 / 对话 / 插件 / 设置**。窄屏不换行；文字过长时使用短标签，不出现第二套 Harness 导航。

- 助手：今日摘要、近期提醒、当前任务；最多一个主要行动按钮。正常状态不展示大量技术卡片。
- 对话：Harness 是常驻标签内容，首次切入按状态自动准备，切出保留草稿、滚动和会话。不得要求再次点击“打开”。不可用时显示原因和唯一推荐操作。
- 插件：同一页面的“发现 / 已安装”视图，共用搜索、详情、状态和操作反馈；Harness 原市场入口路由到这里，不维护第二套安装流程。
- 设置：账号与模型、鲸鱼娘与语音、记忆与资料、提醒与日历、设备能力、存储与运行环境、诊断与关于。终端、运行时版本、兼容诊断收进高级设置。

鲸鱼娘短按展开轻量对话面板，直接使用 Harness 会话。提供收起、停止生成、输入/语音及切换会话。打开 App 时继续同一会话；切换显示容器前先处理输入法和焦点，不重复提交消息。不能同时把同一 WebView 挂在两个父容器：优先由原生宿主管理附着和释放；若现有实现必须使用两份视图，则共享会话数据、只允许一个活动输入端，并明确内存成本。最终方案在 M1 原型实测后确定。

## 4. 视觉与易用性规范

采用统一海蓝强调色、浅/深主题、8dp 间距体系、圆角卡片与三级文字层级。状态颜色必须同时带图标或文字。主操作触控区至少 48dp；支持系统字体放大、TalkBack 标签、安全区域与键盘避让。

常规页面只显示“当前状态 → 可做什么 → 操作”。说明分为一句用途、数据来源、开启影响和详细说明；不以 PRoot、rootfs、桥接等术语作为用户主导航。加载、空内容、离线缓存、权限缺失、损坏和失败分别呈现，不把读取失败显示为“暂无数据”。

统一组件：PageHeader、StatusBanner、SettingRow、PermissionRow、AsyncAction、EmptyState、ErrorState、ConfirmSheet。操作失败保留输入；返回恢复搜索与滚动；长操作显示阶段及取消能力，无法安全取消的提交阶段应说明正在完成写入。

验收视口：360/393/412dp 宽、AYANEO 横屏、大字体 1.3/1.5 倍、键盘展开。截图需覆盖全部四标签及悬浮对话，不只验单页。

## 5. 逻辑归并与模块边界

目标依赖：页面 → 领域控制器 → RuntimeBridge → 原生领域服务 → Harness/系统能力。UI 不拼接底层命令，多个入口不各自拥有后台任务。

| 模块 | 统一职责 | 迁移策略 |
|---|---|---|
| AppShell | 导航、主题、全局错误边界 | App.tsx 逐领域移出，保留旧入口适配器 |
| RuntimeController | 状态订阅、启动/停止请求、诊断展示 | 原生 RuntimeSupervisor 保持生命周期唯一裁决者 |
| ConversationCoordinator | 会话 ID、展示容器、草稿与活动输入端 | 页面与鲸鱼娘通过同一协调器进入对话 |
| PluginService | 目录、安装记录、兼容结果、事务进度 | 市场与管理只做不同投影，安装只走一条后端路径 |
| CompanionService | 记忆、资料、提醒和偏好契约 | 替换宽泛请求为操作联合类型，并校验返回值 |
| CapabilityService | 权限、可用性、授权入口 | 各页面读取同一快照，不自行猜测权限状态 |
| SettingsRepository | 默认值、版本迁移、部分字段更新 | 省略字段保持原值，单次保存不能覆盖其他开关 |

建立桥接契约统一结果：成功数据；或 code、用户信息、是否可重试、操作 ID。异步任务使用 operationId、generation 和数据 revision；旧响应不能覆盖新状态。原生写入成功后再更新 UI，不把乐观显示当持久化成功。

冗余清理顺序：列调用方 → 统一实现 → 旧入口转发 → 回归验证 → 删除失效代码和测试。不要删除启动缓存失效、停止请求取消、依赖单例校验、数据并发版本检查、受限文件路径检查。App 与 Harness 可有不同展示适配层，但不能各自写一份设置。

## 6. 运行时可靠性

启动事务明确记录准备、加载器、访客探测、进程启动、服务就绪各阶段；成功以既有鉴权入口与进程状态为依据。用户可从 App 导出不含凭据的故障分类、运行时版本、设备系统版本和耗时。

对 PROOT_GUEST_EXEC_FAILED：保留原始受限运行日志；按证据区分权限、缺文件、超时等，不能仅凭通用码自动重装。失败使验证缓存失效；下一次重试执行必要检查。自动重试有次数上限，仅限已证明可恢复且不会产生重复副作用的阶段。

设置中提供“重试启动 / 查看诊断 / 修复运行环境”分级入口。修复前核对数据保留范围和存储空间；禁止自动清空用户数据。停止、安装、终端与启动继续共用生命周期锁，避免互相争抢。

## 7. 插件一体化

用户点击安装后直接进入事务，不再跳到另一页批准同一安装。兼容检查在后台自动执行；首次 Android 系统权限或新增数据访问能力仍通过必要授权完成。

事务：解析指定包 → 选择兼容版本 → 下载校验 → 依赖检查 → 等待安全维护点 → 暂停必要服务 → 原子安装 → 回读状态 → 按原状态恢复。空闲对话可自动完成；正在生成或执行任务时显示“等待当前任务完成”，可取消排队，不直接打断外部动作。失败保留旧版本并提供重试/诊断。

目录与安装记录以规范包名关联，核心组件受保护。状态包括未安装、排队、下载、检查、安装、已安装、下次启动生效、失败、可更新。兼容版本回退显示实际版本；不伪装最新版本成功。原生扩展或平台不支持时给出具体限制，不通过删除检查强行安装。

排序支持推荐、下载量、名称、最近更新；更新时间仅在数据源提供时开放。下载量必须显示来源、统计周期和刷新时间，未知显示“暂无统计”，不能补零或混合不同周期。离线保留最近目录并标明缓存日期，失败时不丢搜索和分类。

## 8. 记忆、资料与主动助手

统一数据链：已授权来源 → 本地采集 → 去重/过滤 → 事实或摘要 → 检索 → 对话/提醒。自动记忆开启后无需逐条批准普通记录；保留来源范围、暂停、纠错、删除和撤销近期学习入口。

记忆记录至少含 id、schemaVersion、文本、来源类别/应用、来源记录引用、生成方式、时间范围、更新时间、置信等级、过期时间、revision、状态。事实与模型推断分开；冲突先保留出处并降低置信，用户明确偏好优先。原始通知、摘要、长期偏好分层保存和设定保留期，防止把每条通知永久积累。

删除语义必须明确：删除长期记忆可选同时删除派生摘要；清除来源记录应清理引用和索引，避免下次整理重新生成已删除记忆。检索采用来源/时间过滤和文本匹配起步，测得必要性后再引入向量索引，不默认内置大模型。

跨应用信息限系统授权可获取的通知、使用统计、用户分享/导入、授权接口和可见界面。不能承诺无 root 读取所有应用私有数据库。采集授权与发往模型的范围分开设置；后台整理优先本地规则，云端摘要按明确配置执行，显示目的地和调用预算。

主动服务按价值分级：每日简报、通知聚合、待办/日程候选、相关记忆提醒、跨应用任务模板。普通提示以气泡为主，重要事项发通知；合并重复、遵守安静时段与频率预算。从信息推断的事项标为候选，不能冒充用户已确认的承诺。

## 9. 提醒与任务闭环

一次性、重复、稍后提醒共用持久化调度契约；编辑/取消旧任务、时区变化、重启恢复和错过触发有明确状态。普通后台整理与用户准时提醒分开调度，不用高频轮询模拟精确触达。

任务中心记录目标、来源会话、步骤、状态及结果证据。步骤遵循观察、动作、再观察、核验；暂停/停止后不再调度下一步。发送、购买、删除等有实际外部后果的动作按照当前授权与内容处理，插件安装授权不自动扩大到全部设备动作。

首批拓展选三条闭环：通知聚合成每日简报；分享资料后可检索问答；对话创建提醒并在鲸鱼娘处理完成/稍后。跨应用复杂执行在稳定性达标后推进，不把功能开关存在当作端到端完成。

## 10. 性能计划与测量

先在固定 APK、运行时版本、数据集和设备状态下建立基线，再优化。冷启动与服务已运行的热切换分开；记录样本数、失败率、中位数和 P95。Magic6 暂不可连接时可用 AYANEO 做回归，但不替代 Magic6 故障验证。

| 范围 | 待验证假设与措施 | 初始验收目标（非当前实测） |
|---|---|---|
| 标签切换 | 大组件重渲染、重复加载；拆分订阅、稳定 props、按需加载非对话页 | 热切换 P95 ≤200ms，草稿不丢 |
| 搜索/市场 | 目录解析与过滤阻塞；保留现有 worker、分页、延迟查询，测后再调 | 固定 5000 条样本下输入反馈 P95 ≤100ms |
| 启动 | 重复准备或竞争；保留已验证缓存，按阶段耗时找瓶颈 | 20 次样本报告失败率，不以统一秒数掩盖设备差异 |
| 后台刷新 | 无用桥接调用/重复轮询；核对已有可见性机制，事件优先并带退避 | 隐藏页不执行展示专用刷新；恢复只补一次同步 |
| 内存 | 多 WebView、目录、截图和日志驻留 | 反复切页 30 次后无持续增长趋势，记录 PSS 与回收情况 |
| 耗电 | 悬浮动画、高频采集、后台模型调用 | 熄屏停止装饰动画；对照 8 小时待机记录耗电和唤醒次数 |
| 安装包 | rootfs 主导体积、归档重复 | 固定单个运行时包、ZIP_STORED、摘要校验与对齐；不以 R8 为首选 |

指标不能靠增加轮询或持续保活达成。必要时给用户“省电 / 平衡 / 快速响应”预设，底层仍是一份设置；预热默认和用户停止语义遵循既有守卫。

## 11. 数据迁移与发布

迁移前备份元数据并验证可读取；增加 schemaVersion，幂等迁移，失败恢复旧数据。涉及数据结构升级时旧版回退必须使用兼容读或恢复配套备份，不能只回退 APK。保留凭据、记忆、资料、提醒、会话、插件配置和当前签名。

每次发布记录源码提交、APK/运行时版本及哈希、签名摘要、构建方式与设备测试范围。禁止将测试包覆盖安装成功描述成启动成功。仅向个人仓库提交，不向上游推送。

## 12. 实施阶段与验收门槛

| 阶段 | 交付 | 必测场景 | 完成条件 |
|---|---|---|---|
| M0 可靠性与基线 | 当前架构图、启动诊断、故障样本、调用/性能基线 | 重复启动、启动中停止、失败重试、日志导出 | 原因有证据；无法复现的故障保持未解决 |
| M1 壳与导航 | AppShell、统一主题、常驻对话/悬浮协调、设置分组 | 窄屏/横屏/键盘/大字体、切页、返回、草稿 | 单行导航，无多余跳转，无重复请求 |
| M2 插件整合 | 单一事务、共享状态、目录与管理一致 | 离线、忙碌、取消、兼容回退、安装失败、重启恢复 | 一次点击完成可安装插件；状态回读一致 |
| M3 个人数据 | 有类型桥接、统一设置、记忆来源与删除、提醒整理 | 老数据迁移、并发修改、撤权、删除、重启/时区 | 自动记忆符合开关；无重复提醒、无静默数据丢失 |
| M4 性能 | 基线对比报告、热点优化、后台预算 | 冷热启动、长期运行、数据规模、待机 | 达成已确认预算且功能无回退 |
| M5 功能拓展 | 三条日常闭环、任务中心与恢复 | 网络断开、模型失败、停止任务、结果核验 | 端到端结果可观察、可纠错 |

顺序为 M0 → M1 → M2 → M3 → M4 → M5；性能采样贯穿全部阶段。每阶段可拆为小提交，避免视觉、存储迁移和运行时变更挤在一个发布中。

测试选择受影响领域：前端类型/规范与组件测试、桥接契约、原生策略单测；涉及运行时则加依赖单例和启动脚本检查；发布再跑项目规定闸门与 APK 校验。纯本文档不触发 APK 重建。已有测试失败应标明基线及来源，不通过删除断言获得绿灯。
