## 预览版的使用路径

- 在桌宠输入第一条消息后可继续发送。预览三的直接聊天会并行判断新消息是否独立。任务只接收本句原文；依赖上轮答复、追加或指代时，保留在原会话等待。窗口显示判断中、排队或接取状态。最多暂存 12 条消息，工单另行持久化。
- 从桌宠聊天或长按菜单打开“我的工具”，点已启用的工坊工具即可在桌宠卡片内使用。需要更大空间或收藏结果时点“展开窗口”。收起工具或关闭桌宠面板会销毁内嵌网页，工具版本变化时会核对当前选择。工坊预览、正式工具和桌宠工具沿用同一套脚本隔离，工具无法自行获得资料、文件、网络或设备授权。
- 在设置的界面主题页可选择简约或可爱，同时单独保留明暗模式和强调色。简约使用紧凑圆角与平面卡片，可爱使用较圆的卡片、淡紫背景和桌宠渐变。已覆盖管理外壳和共用桌宠控件。其余原生页面和 Harness 自身界面仍需按屏复核。
- 只有等待用户或受阻的 Worker 时，不再因为这些工单而维持五秒心跳。界面命令继续通过文件监听唤醒，有历史工单时保留十五秒兜底。未送达回执、镜像写入和真正执行中的工作仍保留原来的活动频率。主机安装的运行环境须更新到 `0.3.55-whale-pet-modes` 才会使用这项改变。

## 多工单目标汇总

桌宠「后台任务 → 目标汇总」和应用「后台任务 → 按目标筛选」可查看已有结果和待处理问题。预览十九新增「在主对话分析」。两个真实只读 Worker 对同一发货日期给出不同回执，新的只读主会话通过 mobile_workers 找到了两份报告，指出日期冲突并引用各自工单。这个入口由用户发起；更多来源、更大工单组和长报告的证据覆盖仍待验收。

## 预览十七 · 跨渠道授权复核

上游以来源、发送人、线程和当前策略决定事件如何进入工单，并在原渠道回复。鲸鱼将设置编辑和执行策略分开：手机保存渠道配置时校验读取时的版本；如果另一个窗口已修改配置，旧窗口不能覆盖发送人名单或凭据。渠道运行时一次读取一致的配置和凭据；运行时已有的策略同步、工单撤回、未发送回执处置仍由领域层负责。

在 AYANEO 隔离配置与本地主机领域用例中核对并发保存、身份分离、手机追加与撤回。尚未以真实 GitHub、飞书账号验证接收、回传及撤权传播延迟。[公开原型架构](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/007-architecture.md)

## 原生创造模式的第一条实机路径

Harness 只读会话生成一个 Kotlin 页面。开发者审查它只处理手动输入的文字后，在电脑执行以下命令。设置 JAVA_HOME 和 ANDROID_HOME，并准备本项目 Android 离线构建依赖。
```sh
python scripts/build-native-feature-preview.py examples/native-checklist/Feature.kt --title 清单去重 --out build/checklist-preview
```
输出目录必须是新目录。脚本从受控模板编译，核对独立包名和零请求权限，并输出源码、APK 和含 SHA-256 的清单。每次构建使用新签名。新签名不能直接覆盖同包名旧安装。当前安装由开发者完成，桌宠内审核、启用、撤销、版本回滚与手机端构建仍待实现。
### 预览二十二 · 从桌宠打开原生功能

电脑构建候选时可传入稳定的 --id。同一 ID 下可保留多个已安装版本，一次启用其中一个。工坊通过 Android 文档选择器接收清单，核对固定的原生窗口组件、包名、已安装 APK 摘要、独立 UID 和零请求权限。预览、启用及从桌宠打开均重新验证。导入不会自动启用。工坊与桌宠共用本机启用状态，仅在工具栏挂载时监听变更。点击原生入口成功后收起浮层，让工具获得输入焦点。
### 预览二十三 · 首轮中断后的连续接单

当首条直接回复需要重试时，原请求仍占用自己的对话位置。用户发送不同的消息后，桌宠把它写入独立的待处理记录；判断上下文包含原请求，交办内容只包含新消息。后台回执可以先显示，原对话保留重试入口。普通追问等待原轮结束，再按提交顺序进入历史。已绑定主 Harness 会话时仍沿用该会话的授权和顺序。
