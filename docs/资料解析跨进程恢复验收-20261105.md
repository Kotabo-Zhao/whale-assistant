# 资料解析跨进程恢复验收

## 范围与结果

在 AYANEO 的预览四十四上，实际终止已领取解析工单的应用进程，再由新进程执行生产解析逻辑。最终旧进程 PID 为 31083，新进程为 31194；恢复阶段 0.172 秒通过。保留的工单标识、原件字节、来源和领取次数均符合预期，生成四段可检索正文，旧工单再次执行没有重复入库。

这是独立测试目录中的跨进程持久化与恢复验证。准备阶段使用无副作用的调度预留回调，恢复阶段由测试主动调用生产领取及解析方法；未验证 Android JobScheduler 自动唤醒、强制停止后的自动恢复、Doze、整机重启、长音频中间断点或真实用户资料质量。强制停止后的应用需要重新启动，不能把此次结果描述为系统自行恢复任务。

## 前置条件和隔离

- 开始前检查真实 Worker 执行目录：109 项完成、2 项失败、1 项中断、2 项受阻，没有运行中的 Worker。测试也检查原生任务计数为零、没有用户待解析资料。
- 测试资料位于应用私有的 `parse-restart-acceptance` 目录。正文为合成的多段交付说明，来源标为本地文件。
- 使用隔离偏好关闭测试资料的语义索引与模型记忆整理，不读取模型凭据，不发送请求。
- 准备阶段用原子文件保存测试标记并发出 `ready-to-stop`，之后保持进程存活；主机确认进程 PID 后才执行 force-stop。
- 预期第一阶段会报告 `Process crashed`，不能把它当成功测试。只有第二阶段全部断言通过才构成本次证据。
- 测试后独立目录及偏好已清理，重新打开了主应用；安装包仍为预览四十四，SHA-256 为 `f94f68d942e659b129665d9ced6a4b7f8e5fa6867ba51d6907c84140ea6cce04`。

## 重现步骤

测试类为 `io.deepseekharness.mobile.companion.WhaleParseRestartTest`。为防止全套测试误触发进程终止等待，最终测试源要求显式阶段参数：

1. 运行 `prepareInterruptedParse`，传入 `-e parseRestartStage prepare`。
2. 等待 `parseRestartPhase=ready-to-stop`，核对设备 `pidof io.deepseekharness.mobile` 与 `preparedPid` 相同。
3. 执行 `am force-stop io.deepseekharness.mobile`，确认旧进程消失、准备阶段终止。
4. 运行 `recoverAfterProcessStop`，传入 `-e parseRestartStage recover`。
5. 要求 `oldPid != newPid`、`searchableChunks > 1`、无重复记录，并出现 `OK (1 test)`；确认测试目录已清理，再重新打开应用。

首次试跑恢复到正文提交成功后，因测试请求了超过接口上限的 100 条检索页而失败；修正为 50 后重新执行完整两阶段，得到上述通过结果。原始日志保存在本地 `build/parse-restart-prepare.log`、`build/parse-restart-recovery.log`；通过日志为 `build/parse-restart-prepare-final.log`、`build/parse-restart-recovery-final.log`。通过后新增的显式阶段保护已编译验证，未改变被测恢复逻辑。
