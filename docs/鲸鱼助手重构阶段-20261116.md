## 模拟器

云端机器是 x86_64，`/dev/kvm` 存在。进程用户起初不能读这个设备（`crw-rw---- root:kvm`）。用 sudo 把设备改为可读写后，当前用户可以打开它。这只说明宿主暴露了 KVM，不说明 arm64 客户机能用它加速。

已安装 Android 命令行工具、platform 35、build-tools、模拟器 37.2.13.0，以及系统镜像 `system-images;android-35;google_apis;arm64-v8a`。创建 AVD `whale-arm64` 后启动失败，模拟器原文：

```
FATAL | Avd's CPU Architecture 'arm64' is not supported by the QEMU2 emulator on x86_64 host. System image must match the host architecture.
```

因此没有启动 x86_64 镜像来代替验收。x86_64 壳即使能进系统，也装不上只含 `arm64-v8a` 的安装包，更不能运行其中的 PRoot 与 Node。PRoot、对话服务、Shizuku、无障碍和桌宠悬浮层都仍是真机项目。没有模拟器耗电数据，也不能用来代表 AYANEO。

1. 底部和侧栏主导航只保留「对话」和「我的」。资料、任务、工具从对话页的三个入口进入，也从「我的 → 日常」进入。设备控制、运行环境、诊断仍在「高级设置」。

## 迁移与兼容

- 不迁移、不删除记忆、资料、事项、会话或插件数据。
- 缺键与显式 `false` 不是同一件事。升级后，从未拨过这两个开关的安装会开始允许桌宠使用长期记忆，以及允许对话检索本地资料。检索到的内容仍可能发给当前模型服务。用户可在「我的 → 桌宠与主动跟进 → 助手偏好」关掉。

## 第四阶段：不确定的投递不重放，会话回到日常（2026-11-17）

上一轮把「会话」放进「运行与数据」。这一轮改回「我的 → 日常」，和资料、任务、工具放在一起，不必先打开高级设置。对话页顶栏在窄屏保留进入会话列表的按钮。运行环境、诊断仍在高级设置里。

## 第五阶段：会话页停掉外壳轮询，并在本机编出 arm64 PRoot（2026-11-17）

内嵌会话由原生页面盖住外壳。这时不再每 5 秒读取 Shizuku、无障碍、保活和悬浮球。回到前台仍会读一次。离开会话进入「我的」或其他页后，5 秒轮询重新武装。没有同设备功耗基线，所以不写耗电百分比。

PRoot 按工作流在 x86_64 上交叉编译。命令是 Operit2 `dc4c3a9405dc7ed3ef69b2ac9a6ace65374d77cf` 的 `tools/android-runtime/build_android_tools_wsl.sh`，NDK `android-ndk-r29-beta4`，校验和与工作流一致。本机默认 `awk` 是 mawk，脚本里的 `strtonum` 需要 gawk；装上 gawk 后编过。产物是 ARM aarch64：

| 文件 | 字节 | SHA-256 |
| --- | --- | --- |
| `libdsh_proot.so` | 256816 | `99a14bf65ebbd90fee7fa9dc62b2188ba8b88718ce2ce2da7f92d6d187ae430a` |
| `libdsh_proot_loader.so` | 1632 | `f149774236db1e69b36cc1e4ed3866c7094db2eee52da0d4956aa63a9bb26929` |

`file` 确认两者都是 ARM aarch64。它们在可下载附件里，没有提交进仓库。

rootfs 不能在 x86 宿主上直接跑 `stage-network-tools.sh`：脚本从宿主 apt 复制二进制，宿主是 amd64。先挂上 `binfmt_misc` 并注册 `qemu-aarch64-static` 之后，`podman run --arch arm64 ubuntu:24.04 uname -m` 得到 `aarch64`。在这个容器里跑工作流里的预置和打包步骤。第一次在 `build-embedded-runtime.py` 停下，原文：

```
rootfs URL must be a bounded HTTPS URL without credentials or fragments
```

原因是清单地址写成了 `file://`。打包脚本要求 HTTPS。容器里的 `build-embedded-runtime.py` 后来用了一个并不存在的 GitHub Release 地址跑完了归档；清单里的这个地址只写在 manifest，不在归档哈希里。交付前已改成 `https://bundled.invalid/runtime/rootfs.bundle`。这是脚本对「只内嵌、不提供远端下载」使用的保留域名，应用在内置资产路径上不访问它。没有发布 Release，也没有把这个地址写成可下载的 GitHub 链接。

前端替换在宿主上重跑 `rebuild-rootfs-frontend.py`，没有再在 QEMU 里重压一遍。`verify-bundle.py` 通过：53324 个条目，解压 1262774575 字节。
