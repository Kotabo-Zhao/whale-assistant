# 桌宠停帧恢复修复

## 已复现的缺陷

旧版 .85 在 `OverlayBallService` 中用 `companionFrame` 同时表示动画循环和唤醒入口。刷新时发现 `View.isShown == false` 就将它置空。窗口恢复可见但未发生重新挂载、屏幕广播或偏好变化时，没有重建入口；`wakePetMotion()` 只对非空回调调用 `post`，后续回复也无法救活。

在 Pocket S 的旧版 APK 上运行两个新回归用例，均得到预期失败：隐藏后重新可见不能恢复；停止后收到回复不能播放。日志为 `reports/honor-motion-stop-20261107/old-85-reproduction-pockets.log`。这是可控复现，不代表已证明用户此前每一次停顿都源于此问题。

荣耀初次连续截图未同步记录每张图的屏幕状态，随后确认设备进入自动锁屏；锁屏时截图可能保留旧缓冲。因此这些截图不作为停帧故障的证明。系统动画比例为 1，减少动态未开启，应用服务仍在；这些单次快照同样不能替代连续验证。

## 修复

- `PetOverlayView` 接收窗口和聚合可见性通知；不可见时立即停帧，重新可见时在当前遍历后复核一次，不增加后台心跳。
- 首次布局和重新挂载后的实际可见状态均可恢复回调；每次布局不会重置已运行的动作。
- 新消息或拖动等事件发现回调不存在时，重新创建循环，但不调用会清掉刚收到动作的 `PetActing.resume()`。
- 进入实际隐藏、锁屏、息屏或减少动态时继续不绘制；省电待机仍等到事件才唤醒。
- `dumpsys activity service io.deepseekharness.mobile/.OverlayBallService` 提供纯动画状态，供后续区分正常静止与调度中断。
