# 主人档案与秘书事项

最终版本：0.3.8-preview.83，运行环境 0.3.92-whale-pet-front。

## 在自然对话中自主维护

主人档案和秘书台账是内部能力，App 与桌宠都不新增字段表单、状态选择或专用设置入口。用户自然说出称呼、习惯和本人信息时，Agent 在既有记忆授权和自动保存策略内维护；用户自然交办、改期、报告完成时，维护同一事项。相同事实不重复写入，普通闲聊中的设想不自动变成提醒。

维护成功后继续回应当前话题，不逐条播报字段名、操作编号或数据库状态；信息确有歧义、权限拒绝或需要主人决定时才询问。用户仍可通过自然语言纠正、遗忘或查询，现有长期记忆管理和撤权入口保留。早期 `.81`／`.82` 方案中的显式面板已按最新要求移除。

主人档案直接保存在现有长期记忆库中，通过 `profileKey` 区分字段，没有另造一份独立的用户资料。秘书事项复用现有理解队列数据库、事项状态、提醒期望和统一备份，只增加事项背景及操作去重记录。两者均位于应用私有目录的 rootfs 之外。

档案与用户主动交办的秘书事项共同遵守长期记忆访问开关，桌宠另外遵守桌宠记忆访问开关。无需为秘书事项开放通知读取。原有通知、资料来源事项仍保留各自的授权边界，没有新增授权开关。

## 每轮稳定加载

- App 在运行时 `system-prompt/assemble` 异步阶段读取本机档案和事项，加入当前系统上下文，不依赖模型决定是否检索。
- 桌宠普通回复、独立并行回复和主动跟进判断使用同一个 `OwnerContext`。角色卡只改变表达，档案存储不随角色、话题或会话切换。
- 档案包含称呼、语言、时区、城市、工作身份、沟通习惯、作息、设备、项目、近期安排。近期安排必须有有效期。
- 每次读取有明确的 confirmed、pending、conflict、expired、empty 状态。只有 confirmed 提供当前事实，冲突、过期、未确认字段不会回退到旧值。读取失败明确表示 unavailable，不缓存上一轮个人信息。
- 采用专用档案索引；每轮最多载入 8 条待处理事项及 8 条关闭事项摘要。待处理事项按截止时间排序，返回下一页位置，完整事项仍可分页查询。
- 本机时间及时区随快照提供；桌宠在回复完成时再次核对数据及权限，变化后丢弃过时答复。App 在下一次模型调用重新组装上下文。
- 完整主人档案不会自动注入 Worker。前台只能将本项任务实际需要的背景交给 Worker。

## 写入与纠错

`mobile_owner_profile` 提供 get、set、forget。自然表达本人事实无需先说「记住」；模型维护遵守现有自动记忆确认设置，用户明确关闭自动保存时仍保留待确认策略，不绕过已有选择。已有管理入口手动修改即确认，已确认字段可按用户自然纠正更新。

每个字段都有内容版本；更新必须回传当前版本，重复操作编号可重试，不覆盖并发修改。有限历史记录保留来源和变化时间；会话来源来自可信运行时参数。忘记会移除字段及其历史，并加入现有删除抑制记录，旧备份或自动记忆不能据此恢复已遗忘内容。

工具只允许当前实际用户输入发起写入。协调消息、后台 Worker 回执和上下文快照不能冒充用户；模型提示另外区分真实本人表态、角色扮演和第三方引文。该来源检查不等同于能确定任意自然语言的真实身份，因此没有把旧的散文记忆自动推断为新主人档案。

## 秘书事项闭环

`mobile_secretary` 提供 list、create、update、delete。事项包含标题、补充背景、下一步、等待对象、截止时间和独立提醒时间。open、done、cancelled 是持久状态；聊天语气和 Worker 自报完成不会自动关闭事项。

- 操作编号、事项、状态和提醒期望在同一 SQLite 事务中提交；断线后重试同一操作不会创建第二条。
- 同名待处理事项拒绝重复创建，需读取后修改原事项；不把不同表述的事项强行合并。
- 更新和删除需要当前版本，避免覆盖用户刚做的调整。
- 改截止时间但没有明确的新提醒，会停用旧提醒；完成、取消、删除也会停用提醒。重新打开不会恢复旧提醒。
- AlarmManager 投递前再次核对事项状态、时间和提醒版本；旧闹钟即使抵达也不能产生过时通知。
- 提醒已到时仅表示时间经过，不冒充送达。写入回执的 scheduled=true 需要与本机实际安排记录一致；安排失败保留事项并标记 pending_repair，后续恢复负责补安排。
- 完成和取消会清掉该事项的系统通知；重复接收同一提醒不会二次通知。
- 恢复备份保持当前修改和遗忘标记优先，导入的提醒等待重新核对，不能靠旧备份恢复执行。
- 主动跟进可参考确认过的称呼和沟通习惯，以及已关闭事项摘要，但仍必须具有最近对话和资料的新证据，继续遵守已有的事项去重。

## 统一的前台对话

Worker 原始结果只留在内部执行台账。协调者合并状态变化、核对证据，再通过 `mobile_coordinator report` 发布自然总结；App“小鲸近况”和桌宠共享该收件箱。普通进度不通知，完成、关键受阻或需要主人决定时才主动说话。汇报指纹和已送达事项状态持久化，重试不重复显示；失败投递不会提前标记为已经告知。

最近三条总结作为背景加载到前台，用户简短追答可继续原事项。它们不是新的用户授权，也不会作为额外助手消息塞进要求用户／助手交替的聊天历史。旧结果、正常工具次数与内部调度过程不再反复播报；桌宠仅显示当前回复的最终草稿。已核验评分插件的自动重写监听已移除，防止缺少档案、工具回执和异步状态的评分修改正确答案；任务完成仍以实际回执与目标核验为依据。

App 的任务页默认近况，保留个人待办供主动查看；运行环境、设备与日志放入高级设置。档案维护工具、协调工具和上下文事件在对话页不直接展示，用户追问、权限决定和正常答案仍可见。

查询包含持久的 `reportedToUser` 状态，概览默认不返回已送达结果正文，按 id 查询仍保留原文供核验。投递失败不会提前设为已汇报；新的任务版本或结果状态变化会清除旧结果的已告知判定。标记不参与协调指纹，防止送达本身制造下一次无效唤醒。

## 实现边界

这是本机个人助理的数据与提醒闭环，不是跨设备同步、外部日历双向同步或完整联系人关系图。长篇旧对话仍保留原文，忘记档案不会宣称从所有历史聊天或外部模型服务删除文字。旧的非结构化记忆继续使用原检索路径；只有明确表达并保存到档案的内容保证每轮加载。系统省电策略可能延迟提醒，已安排也不等于一定准点送达。
