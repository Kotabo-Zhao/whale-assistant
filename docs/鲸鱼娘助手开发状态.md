# 鲸鱼娘桌面助手：开发状态

## 2026-11-02：荣耀桌宠实机验收

- 已覆盖安装并启动当前调试版。在桌宠设置中临时选择“仅查看”，随后真实设备电池查询的后台会话记录了 `read-only` 权限与沙箱模式，权限命令成功；验收后已恢复“跟随主应用默认”。
- 桌宠实际调用 `mobile_device_battery`；该次后台一条有文本的助手消息与桌宠保存的答复均为 1,037 字，逐字比较一致。该样例未覆盖一次任务中的多条有文本消息，也未触发单次审批提示，因此这些情况仍需真机验证。

## 2026-11-02：桌宠后台回复完整性

- 修正此前“工具任务直接显示 Agent 回复”的实现：同一轮的多个助手消息按顺序保留，不再被最后一条覆盖；保留文本块并按消息标识去重。资料查询不再因未检测到指定工具而丢弃首个答复、强制重试或替换为固定提示。
- 桌宠显示的是助手可见文本；工具内部结果、思考内容、附件及资料来源仍按各自界面能力处理，不表示与主对话每个面板完全一致。单条实际回复的荣耀对照结果见上方验收记录。

## 2026-11-01：桌宠会话权限与回复一致性

- 助手设置中新增桌宠会话权限预设：跟随主应用默认、仅查看、工作区内修改和完全权限。独立桌宠 Agent 会话使用选择的预设；更改后下一次任务建立新会话应用。完全权限关闭 Harness 文件系统沙箱和命令审批，不替代 Android 系统授权。接续主对话时沿用主会话权限。
- 收到 Harness 审批请求时，桌宠显示需要处理的提示并提供主对话入口；实际审批仍通过主对话完成。主对话审批服务是否可用需真机验证。
- 之前后台 Agent 答复会再交给角色模型重新生成，且角色直连上限为 400 token、后台答复超过 2000 字会被校验拒绝。现在工具任务直接显示 Agent 的回复，Agent 本身仍接收角色卡；角色直连提高生成上限，长回复可保存到桌宠历史。普通角色聊天仍由角色模型生成，模型服务本身仍有输出长度限制。
- 荣耀已验证“仅查看”模式和一条助手文本的一致性；审批提示和多段助手文本仍待真机验证。

## 2026-11-01：资料路由和桌宠语音

- 桌宠在角色对话前使用所选 DeepSeek 模型结合最近六条消息做语义意图判断，区分普通聊天、资料查询与其他工具任务，不用关键词表路由。需要资料时委托 Harness，资料访问未授权时提示用户；模型被要求按工具回执报告执行结果，仍可能误判或答错。该判断增加一次短模型请求，也可能误判；明确接续主会话或没有 DeepSeek API Key 时沿用原有 Harness 路径。
- 因音色效果不符合要求，用户要求移除新增的桌宠本地语音模块；Paraformer 和 Kokoro 模型已从荣耀删除，本次新增的 sherpa-onnx 接入和桌宠语音界面也已移除。
- 用户进一步要求移除所有语音入口：主对话、悬浮球和桌宠的语音输入、朗读入口与对应实现均已移除，保留共享文本的输入功能。荣耀已覆盖安装并启动；安装包 527.8 MiB，检查未发现上述语音模型或 sherpa JNI 库。
- 桌宠对缺少信息的任务引导模型直接提问并等待文本回复，意图分类结合前文识别追问的回答。若 Harness 仍调用结构化提问工具，桌宠显示问题并提供“主对话”入口；结构化答案尚不能直接在桌宠提交。针对性构建与单测通过；荣耀自动化两轮追问测试长时间未返回，终止以完成安装，端到端效果尚未验证。
- 荣耀实机资料请求已确认调用 `mobile_knowledge_search`、`mobile_knowledge_hybrid_search` 等工具；语义分类对前文指代、不查询及设备查询的三个样例通过。

## 2026-11-01：桌宠角色直连

- 桌宠改为统一对话：配置 DeepSeek API Key 时，角色模型使用角色卡、世界书和近期对话流式回复；需要查询或操作时自动委托 Harness，按原有权限访问记忆、资料、事项与设备，再由角色根据结果回复。不再要求用户切换模式。未配置该 Key 或明确接续主对话时，继续使用原有 Harness 路径。
- 荣耀实机对照：当前角色卡、同一条非露骨成年约会输入、`deepseek-flash` 下，旧 Harness 路径和直连均返回了非拒绝回复；该样例没有复现用户报告的拒绝，不能证明限制来源，也不能保证其他输入的结果。Harness 观察到较长系统提示、工具及高强度思考配置，直连使用角色系统提示和非思考模式。
- 荣耀实机已覆盖安装融合版，普通角色聊天流式输出通过；实际查询电量时角色模型自动委托 Harness，设备会话记录了 `mobile_device_battery` 工具调用，随后角色生成流式回复。该测试未覆盖所有工具及资料权限组合。模型服务仍可拒绝请求，角色设定不保证绕过服务端限制。
- 构建与 TypeScript 检查通过；仓库全量 Android 单测 1817 项中有 3 项旧的资料长度上限断言失败、37 项跳过，前端测试有 1 项旧导航断言失败，ESLint 与脚本全量测试也有既有失败，需另行清理。

## 当前可用的代码路径

- 复用原有悬浮窗前台服务：鲸鱼娘轻微上下浮动、可拖动，短按展开快捷入口，长按打开已有 Harness 对话小窗。启用依赖系统悬浮窗权限和应用内悬浮球开关。
- 设置 → 后台保持 → 鲸鱼娘助手设置：通知摘要采集与休息提醒分别默认关闭；通知读取和应用使用情况访问分别由用户到系统设置授权。
- 开启采集并获得系统通知读取权限后，保存新到达通知的包名、标题及正文，最多 50 条；查看或新增时清理 7 天前记录，可手动清空。忽略本应用、持续型通知和系统标为 secret 的通知。密码、验证码等采用简单规则过滤，不能保证完全识别。
- 按按钮读取系统最近 7 天使用统计和本地通知计数；系统返回的日统计可能包含边界时段。可手动复制通知计数摘要，用户自行决定是否粘贴给模型；没有自动上传或自动喂给 Harness。
- 提醒开关打开且悬浮服务运行时，约每 90 分钟展示休息气泡；低电量（15% 及以下且未充电）每 15 分钟检查，通知最短间隔 12 小时，要求通知权限。通知到达时只显示不含内容的提示，气泡不在锁屏或熄屏时显示。
