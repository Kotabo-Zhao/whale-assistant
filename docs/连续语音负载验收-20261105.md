# 连续语音负载验收

在 AYANEO 的预览四十五上补测持续语音，而非只有开头和末尾说话的长静音文件。使用仓库既有普通话样本（单声道、16 kHz、16 位 PCM、5.685 秒）重复 116 次，得到 659.46 秒的 WAV；没有加入十分钟静音，也不需要模型联网。该样本包含“明天下午三点开会，请带上蓝色的笔记本”。

最终本地识别耗时 45,082 毫秒，约为音频时长的 6.84%；生成 113 段带时间戳的文字，末段起点 656 秒。时间戳不倒退，开头六秒内保留开会和笔记本内容，末段保留笔记本内容，没有触发正文截断。恢复测试整体 45.348 秒，`OK (1 test)`。此处的耗时是热设备上的单次结果，不是性能分位数或首次安装体验保证。

测试显式要求 `-e continuousAudio true`，否则跳过，避免普通套件隐式触发持续负载。开始前断言没有运行中的 Worker 和用户待解析资料。临时 WAV 在应用缓存中生成并在 finally 删除；不写用户资料库、不改模型设置。测试 APK 更新，主应用仍是预览四十五，未发布新主版本。

首次及诊断重跑的断言失败源于将“第一条转写”误当成“完整首句”。实际首段为“明天下午三点开会”，第二段包含笔记本，属于识别分句。最终改为检查原样本开头六秒内的完整语义，再完整重跑通过；没有降低末段、顺序和截断要求。

日志：本地 `build/continuous-audio-device.log`（首次）、`build/continuous-audio-diagnostic.log`（分句诊断）、`build/continuous-audio-final.log`（通过）。测试类为 `WhaleContinuousAudioTest`。处理中的一次 PSS 采样为 312,558 KiB，约 305 MiB，仅为瞬时样本，未测峰值。

本轮仅验证持续解码、离线识别及首尾时间覆盖。重复短语容易识别，不能证明真实多人会议、背景噪声、口音、说话人区分或长音频检索质量；也未覆盖长录音中断续接、其他容器编码、离电耗电和温度。上述缺口继续保留。
