# 后台理解开发记录（2026-10-30）

## 基线核对

保留原有插件维护、记忆迁移和归档的未提交工作。提醒策略被工作区改动移除，但既有单元测试仍引用；恢复提交版的策略及调用，避免破坏测试与时间边界。

前端 TypeScript、ESLint 和完整 Vitest 通过（79 个文件、1055 项）；脚本测试 400 通过、4 跳过；质量闸门通过。Android 使用本机 SDK 和 JDK 21：单元测试 1733 项，其中 1696 通过、37 跳过；Android 设备测试源码编译通过。

## 本批：持久化任务队列基础

新增独立 SQLite 队列，只保存来源标识、输入摘要、授权代次和任务状态，不存正文或凭据。支持同一来源、代次和输入去重；领取令牌与代次用于拒绝旧结果；撤销来源时取消待处理及在途任务；支持延迟重试和独占工作器启动后的中断恢复。来源授权默认不存在，必须显式启用。

新增设备端测试覆盖持久化、去重、撤权与重新授权、重试和中断恢复。本机无已连接 Android 设备或模拟器，测试仅编译，尚未运行。队列尚未接入采集、调度、网络、模型或 UI，不会自行处理用户信息。

现有记忆迁移库仍是暂存实现：正式读取与写入仍走旧 JSON 文件，原有容量限制未解除。当前队列完成操作只更新队列状态；未来接入理解结果时，必须将结果校验、数据库写入和完成标记放在同一事务，不能先调用完成再写结果。中断恢复仅允许在确认旧工作器已经停止的独占启动阶段调用。

下一步先在 Android 设备运行数据库测试，再设计统一数据库中的事件、权限、队列与结果事务，随后接入明确授权的来源、模型预算和可观察运行状态；迁移切换前必须验证旧数据、回滚和删除抑制语义。

## 后续开发：统一暂存与模型处理

新增 `UnifiedUnderstandingStore`：记忆迁移和后台理解使用同一个私有 SQLite 文件；事件与任务同事务写入，候选结果与任务完成同事务提交。来源撤权会使未提交的旧任务失效；事件标识冲突报错，不静默覆盖。候选结果必须引用实际输入事件，结构和长度不合法时拒绝保存。可限量读取最新候选，尚不是正式记忆或提醒。

新增 DeepSeek 非流式模型客户端与既有加密凭据、默认模型读取入口。不跟随重定向，不记录正文或密钥。只实现 DeepSeek 协议，尚未接入其他模型供应商。模型请求发生在事务之外；请求中途撤权可阻止结果入库，但无法撤回已经发送的数据。处理器需要调用者先明确获取来源和云端分析许可；目前没有调用入口或调度，也没有自动发送用户数据。

迁移暂存后可生成旧格式回退导出；旧 JSON 文件及现有正式读写路径保持不变。回退导出受旧格式容量限制，不是新数据库任意规模数据的通用降级方案。删除抑制仍在旧设置中，尚未纳入新库回退导出；正式切换前必须解决这一点。编写了迁移、重启、回退导出、失败回滚、撤权与结果提交的 Android 设备测试；无设备时只可编译，不能称实际迁移和回滚已验证。还需完成授权界面、来源接入、后台调度、预算、模型协议适配、删除抑制和统一正式读写，然后在设备上验证故障恢复与数据安全。

## 桌宠气泡对话

悬浮桌宠短按改为原生气泡聊天，不启动或打开 Harness；长按菜单仍可进入 Harness。聊天使用现有 DeepSeek API Key 和默认模型，消息发送到 DeepSeek；暂不支持其他供应商、Harness 登录凭据、工具调用或共享 Harness 会话。会话和草稿保存在悬浮服务内存，服务结束后不保留；失败保留草稿。设置页提供两项独立、默认关闭的选择：允许聊天发送相关已确认记忆，以及允许根据已确认记忆主动搭话。主动搭话本地生成，最多每日一次，避免连续重复同一条，遵守屏幕解锁及免打扰；可能被旁人看到，开启前显示说明。

Android 单元测试和调试构建通过，设备测试源码可编译；没有连接设备，悬浮权限、键盘、窗口尺寸、主动气泡、真实模型请求、长期运行和机型适配尚未实测。本功能不代表后台模型理解或数据迁移已完成。

## 后续开发：通知后台理解接入

上述“没有调用入口或调度”的旧状态已被本节替代。设置页新增默认关闭的通知后台理解授权；开启后只处理授权采集、未排除应用的新通知。通过系统 JobScheduler 在非计费网络上调用已配置的 DeepSeek，每日最多 20 次尝试，失败延后重试。模型结果仍是附带来源和原文依据的候选，用户可在设置页查看或清空后台事件、候选及待处理任务。停止后台理解或通知采集会取消作业、作废来源代次；排除应用同样作废相应来源。系统中断、通知监听断开、网络和系统省电仍会影响处理时间；向外发送后不能撤回。

设置页新增“校验长期记忆迁移副本”，复制旧记忆快照到暂存库并核对旧格式导出；正式读写仍为原 JSON。这个操作不迁移删除抑制，不等于已验证完整回退或切换。设备端测试覆盖队列撤权与迁移，但没有连接设备时仍只能编译；也尚未完成真实网络、撤权竞态、后台调度和功耗的设备验收。候选不会自动写入正式记忆，也没有事项调度、模型质量评估或完整的逐条纠错与删除传播。

## 后续开发：可选切换与候选入库

设置页新增手动切换：迁移时在同一进程锁内读取旧 JSON，导入或刷新 SQLite 快照并核对内容和旧格式导出，最后保存数据库启用标记。启用后既有记忆接口读写 SQLite；数据库丢失或不可读时拒绝回退到可能过期的旧文件。回退时先将当前 SQLite 内容原子写回 JSON 并验证，然后切换标记；本机原有的自动记忆删除抑制设置仍保留。旧 APK 不读取新库，安装旧 APK 前必须在新版中先执行回退。此路径仍沿用现有 100 条及整库加载限制，不代表已完成无固定条数限制的存储重构；现有导出格式也不包含删除抑制信息，不可作为跨设备完整恢复方案。

后台候选可查看通知依据，由用户确认后保存为记忆，保留来源及事件标识；若原事件已清空，记忆管理界面说明依据不可用。导入会验证并保留这些标识。编辑记忆时去掉旧依据标识。尚未实现后台候选自动保存、冲突与纠错传播、删除防重建和提醒事项状态机。

新增迁移后写入、重启读取、回退后再迁移、删除抑制保留以及数据库缺失时拒绝旧数据回退的 Android 设备测试。测试源码已编译；无已连接设备时这些测试无法实际执行，切换、断电恢复和系统调度不应描述为真机验收通过。

## 后续开发：自动记忆、备份和事项基础

SQLite 模式去掉 100 条写入限制，旧 JSON 模式保留旧限制；检索偏移不再受 100 条限制。现有界面与部分操作仍整库加载和全量改写，尚未经过十万或百万条规模测试；单次 JSON 备份最多 8 MB，不能当成无限规模方案。超过旧格式容量时不能直接回退旧 APK，先导出新版备份，并在新版 SQLite 环境恢复。

记忆删除会保存规范化文字摘要，自动记忆和备份导入会检查这些标记；用户明确重新添加时解除该文字的标记。新版记忆备份包含自动整理暂停状态、来源暂停和删除摘要，导入只合并抑制记录，不以旧备份解除当前删除。旧版备份不含删除记录；此机制只阻止相同规范化文字，不能识别语义改写，也不能防止包含敏感内容的摘要被字典猜测。记忆备份不包含后台事件原文、事项及队列状态，恢复后证据可能不可用。

SQLite 模式新增独立、默认关闭的后台自动记忆开关。合法模型结果、事项候选、自动记忆与任务完成状态在同一 SQLite 事务提交；来源和证据标识保留，自动记忆标为待核实，用户可确认、编辑或删除。事项目前支持待核实、待处理、完成、取消及查看依据，不自动解析截止时间、不发提醒，也未实现跨通知合并或改期处理。

新增单元测试与设备端数据库测试；设备端测试仍需连接 Android 才能执行，真实模型、长期负载、进程中断、备份跨设备恢复和机型体验均尚未验收。调试包不等于发布版本。

## 后续开发：分页、索引与后台备份

SQLite 原生记忆列表按 50 条分页，游标绑定修订号，列表变化后需重新打开；普通记忆写入只更新新增、删除或变动的行，自动记忆去重改为查询摘要索引。既有数据库首次打开时在事务中建立索引；搜索、部分桥接和备份仍会整库加载，尚不能宣称已完成大规模优化。

删除记忆时除文字摘要外，还记录来源事件标识摘要，阻止同一事件用不同措辞自动重建；新版记忆备份可携带这两类删除记录，导入会与当前记录合并。不同事件对同一事实的改写仍无法可靠识别。

后台事件、模型结果、事项和已清除的事件标识可单独导出为未加密 JSON，导入时在事务内校验并合并，不恢复授权、排队任务或覆盖已有事项状态。清空后台数据时留下事件删除标记，导入旧备份不会恢复本机已清除的事件。记忆与后台是两个独立备份，单个文件限 8 MB；没有跨文件原子快照，也不能凭过时备份推知另一设备之后的删除。

事项界面可手动创建独立提醒；事项状态改变不会同步取消该提醒。自动合并、改期及提醒关联仍未实现。新增数据库事务、索引、分页和备份的设备测试；没有连接设备，未执行设备测试或真实跨设备恢复。

## 后续开发：索引检索、跨事件抑制和关联提醒

SQLite 模型记忆搜索新增字符与双字索引；首次打开旧数据库时在事务中建立索引，新增、修改、删除与自动记忆提交会同步维护。精确匹配通过索引筛选后核对原文，关联回退最多评估 200 个候选并明确提示可能遗漏；近期列表使用数据库分页。搜索、自动去重不再把全库装入内存，但首次建索引、常见字候选扫描、旧界面和部分写入仍可能随库增长变慢；尚未进行 1 万、10 万、100 万规模实测。

删除保护增加规范化字符对的摘要集合，用保守的重叠阈值拦截跨事件的近似改写，随记忆备份保存；可能误拦无关句子，也不能识别所有语义改写，短文本仍只靠原有精确摘要和来源事件。摘要有被字典猜测的可能，不应视作加密。用户明确重新保存相近文字时，相关抑制标记会移除。

新通知保存系统通知身份摘要和时间。同一个通知的后续更新，只有唯一待处理或待核实事项、单一新事项且标题一致或高度相似时才合并，并保留证据与用户状态；已完成或取消的不自动重开。事项可由用户设置关联提醒；完成或取消会使其失效，投递前再次校验事项状态及时间。明确改期且新旧时间均可可靠解析时，保留用户设置的提前量并更新提醒；若改期时间不明确则暂停旧提醒并标为待核实。不同通知身份、多个候选、歧义时间或不相似标题不自动合并；不能保证模型和启发式判断正确。

后台备份增加通知身份、事项证据和提醒时间；恢复后提醒需要用户重新核对，不自动调度。设备端测试包含索引搜索、跨事件抑制、关联事项与改期，仍因无设备而只能编译。尚未验证 Android 报警竞态、断电恢复、跨设备恢复、真实模型质量或长期性能，不应将调试构建视为已验收发布版。

事项提醒的数据库状态和系统闹钟不能组成同一个事务：保存后立即尝试安排，并在应用打开或设备启动时恢复；旧闹钟触发时也会先核对并尝试恢复。若进程在保存新时间后、安排系统闹钟前被终止，且新时间早于旧闹钟、期间应用未恢复，提醒可能错过。该窗口尚无完整持久调度器验证，不能保证及时投递。
